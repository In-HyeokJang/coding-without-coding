## 시작하기 전에

이 커뮤니티에서 여러분이 진짜로 배우는 기술은 **코딩이 아니라 프롬프트**입니다.

AI는 코드를 씁니다. 여러분은 뭘 만들지 정하고, 그걸 말로 전달합니다.
3주 뒤에 남는 근육은 그거예요.

---

## 프롬프트 4원칙

### 원칙 1 · 한 번에 하나만

AI에게 열 가지를 한 번에 시키면, 여덟 개는 대충 하고 두 개는 엉뚱하게 나오기 쉽습니다. 그리고 뭐가 어긋났는지 찾기가 어려워져요.

**나쁜 예**
> 홈 화면 만들고 상세 페이지도 만들고 로그인 붙이고 색깔도 예쁘게 해줘

**좋은 예**
> 홈 화면을 만들어줘. 상단에 제목, 아래에 리뷰 목록 5개가 보이면 돼.

하나 끝나면 다음 걸 시킵니다. 이게 결과적으로 훨씬 빨라요.

**요령:** 시키고 싶은 게 세 개면 종이에 셋 다 적어두세요. 그리고 하나씩 지워가며 물어봅니다.
그래야 빠뜨리지 않으면서도 한 번에 하나만 시킬 수 있어요.

> 이 습관은 `CLAUDE.md` 에 적어두면 AI가 대신 지켜줍니다.
> `- 한 번에 하나씩만 한다. 여러 개를 시키면 하나만 하고 나머지는 되물어라.`

---

### 원칙 2 · 결과를 묘사한다, 방법을 지시하지 않는다

우리는 코드를 모릅니다. 그러니 "어떻게"를 시키기보다 **"뭐가 보였으면 좋겠는지"** 를 말하는 편이 좋아요.

**나쁜 예**
> useState 훅으로 상태 관리해서 map으로 렌더링해줘

(모르는 말을 쓰면 의도가 엉뚱하게 전달되기 쉽습니다)

**좋은 예**
> 리뷰를 입력하고 저장 버튼을 누르면, 아래 목록에 방금 쓴 리뷰가 바로 나타나면 좋겠어.

방법은 AI가 알아서 고릅니다.

---

### 원칙 3 · 구체적으로. 특히 숫자와 위치

**나쁜 예**
> 좀 예쁘게 만들어줘

**좋은 예**
> 배경은 흰색, 글씨는 진한 회색으로 해줘. 제목은 크게, 본문은 읽기 편한 크기로.

**나쁜 예**
> 버튼 추가해줘

**좋은 예**
> 리뷰 목록 위쪽 오른편에 "리뷰 쓰기" 버튼을 넣어줘.

---

### 원칙 4 · 안 되면 상황을 설명한다

이게 제일 중요합니다. 에러가 났을 때 "안 돼요"라고만 하면 AI도 알기 어려워요.

**나쁜 예**
> 안 돼

**좋은 예**
> 저장 버튼을 눌렀는데 아무 일도 안 일어나. 화면도 안 바뀌고 에러 메시지도 안 보여.
> 터미널에는 이렇게 떠 있어:
> [에러 메시지 그대로 붙여넣기]

## 좋은 프롬프트 vs 나쁜 프롬프트

| 상황 | 이렇게 말고 | 이렇게 |
|---|---|---|
| 처음 만들 때 | "쇼핑몰 만들어줘" | "상품 목록을 보여주는 홈 화면 하나만 먼저 만들어줘" |
| 고칠 때 | "이거 이상해" | "제목이 화면 왼쪽에 붙어 있는데, 가운데로 옮겨줘" |
| 에러 났을 때 | "에러 나" | "터미널에 이 메시지가 떠. [붙여넣기] 뭘 확인해야 해?" |
| 이해 안 될 때 | (그냥 넘어감) | "방금 만든 파일 3개가 각각 무슨 역할인지 한 줄씩만 설명해줘" |
| 되돌리고 싶을 때 | "아까로 돌려줘" | "방금 바꾼 파일을 되돌려줘. 그 전 상태로." |

### 2회차 · 페이지 목록 뽑기

```
나는 [               ] 사이트를 만들고 싶어.
쓰는 사람은 [               ].

첨부한 스크린샷은 참고하고 싶은 실제 사이트야.
이걸 참고해서, 내 사이트에 필요한 페이지 목록을 뽑아줘.
각 페이지에 뭐가 들어가는지도 같이 적어줘.

아직 코드는 만들지 마. 목록만.
```

목록이 나오면 이렇게 좁힙니다.

```
3주 안에 혼자 만들 거야. 지금 목록에서 꼭 필요한 것만 남기고 줄여줘.
페이지는 [3]개 이하로.
```

**내 CLAUDE.md 만들기**
```
이 폴더에 CLAUDE.md 파일을 만들어줘.
아래 내용을 기본으로 하되, 내 아이디어에 맞게 고쳐서 만들어줘.

(준비 → 토큰 절약 설정 의 템플릿을 여기 붙여넣기)
```

### 3회차 · 페이지를 전부 만들고 서로 잇기

3회차는 **뼈대**를 만드는 날입니다. 디자인은 넣지 않습니다.

**① 시키기 전에 30초 확인**
```
CLAUDE.md 의 페이지 구조 부분을 그대로 읽어서 보여줘.
설명은 붙이지 말고 목록만.
```

**② 한 번에 시키기** — 팀 소집 + 프로젝트 생성 + 페이지 + 링크를 한 덩어리로

따로따로 시키면 AI가 매번 처음부터 다시 읽어서 사용량이 더 나갑니다. 한 번에 묶습니다.

```
너는 지금부터 2명으로 일해줘.

1. 기획자 — CLAUDE.md 의 페이지 구조를 기준으로, 빠진 화면이나 앞뒤가 안 맞는 곳을 찾는다
2. 개발자 — 그 구조대로 파일을 만든다. 가장 단순한 방법으로만

일하는 방식:
- 회의 내용은 보여주지 마. 결론과 실제로 만든 것만 짧게 말해줘
- 오늘은 뼈대만 만든다. 디자인·색·글꼴·간격은 절대 손대지 마
- 기능도 넣지 마. 버튼은 눌러도 아무 일 안 일어나도 된다

[오늘 할 일]
이 폴더에 Next.js 프로젝트가 아직 없으면 먼저 만들어줘.
TypeScript로, 기본 설정으로, 질문하지 말고 그냥.

그다음 CLAUDE.md 의 페이지 구조에 있는 페이지를 전부 만들어줘.

지킬 것:
- 목록에 있는 페이지는 하나도 빠뜨리지 말 것
- 페이지끼리 링크로 이어줄 것
  · 홈에서 카드를 누르면 그 상세 페이지로 넘어간다
  · 상세 페이지에는 홈으로 돌아오는 링크가 있다
  · 페이지가 3개 이상이면 맨 위에 메뉴를 만들어서 다 걸어줘
- 페이지마다 "여기에 뭐가 들어갈 자리" 인지 글자로 적어둘 것
- 목록이 필요한 화면은 가짜 데이터 3개만 넣을 것
- 스타일·색·글꼴은 손대지 마. 기본 상태 그대로 둬

시작하기 전에, 무슨 파일을 몇 개 만들지 목록으로 먼저 보여줘.
```

목록을 읽어보고 이상하지 않으면 `좋아. 그대로 만들어줘.`

> **링크를 같이 거는 이유** — 안 걸면 홈 말고 다른 페이지는 열어볼 방법이 없습니다.

**③ 화면 켜기**
```
지금 만든 걸 브라우저에서 볼 수 있게 실행해줘.
```

브라우저 주소창에 `localhost:3000` 을 치면 내 사이트가 뜹니다.

**④ 돌아다니다 마음에 안 드는 곳만 고치기** — 여기서부터는 한 번에 하나씩
```
[               ] 페이지에서 [               ] 부분을 고치고 싶어.

지금: [               ]
이렇게 됐으면 해: [               ]

이거 하나만 고쳐줘. 다른 파일은 건드리지 마.
```

> 마지막 줄을 빼먹으면 AI가 옆 페이지까지 같이 고쳐놓습니다.

### 4회차 · 기능 붙이기

**먼저 폼만 (저장은 나중에)**
```
홈 화면에 [리뷰를 입력하는 폼]을 추가해줘.
입력 칸: [카페 이름], [별점], [한 줄 평]
저장 버튼을 누르면 아래 목록에 바로 나타나면 돼.

아직 데이터베이스는 연결하지 마. 화면에서만 되면 돼.
```

**그다음 Supabase 연결**
```
이제 Supabase에 연결해줘.

내 Supabase 정보야:
Project URL: [여기에 붙여넣기]
anon key: [여기에 붙여넣기]

테이블 이름은 [reviews] 이고, 칸은 [name, rating, comment] 야.

리뷰를 저장하면 Supabase에 들어가고,
새로고침해도 목록이 그대로 남아 있게 해줘.

키는 .env 파일에 넣어서 코드에 직접 안 보이게 해줘.
```

### 5회차 · 다듬기

```
지금 화면에서 이 부분을 고치고 싶어:
- [제목 글씨가 너무 작아. 두 배 정도 크게]
- [카드 사이 간격이 좁아. 조금 띄워줘]
- [배경이 흰색인데 아주 옅은 회색으로]

한 번에 하나씩 하고, 하고 나면 알려줘.
```

```
휴대폰 화면에서 봤을 때도 안 깨지게 해줘.
```

```
브라우저 탭에 뜨는 이름을 [내 카페 기록] 으로 바꿔줘.
```

**배포 예행연습 + GitHub 올리기** — 검사와 저장을 한 번에
```
npm run build 를 실행해서 에러가 없는지 확인해줘.
에러가 있으면 뭐가 문제인지 알려주고 하나씩 고쳐줘.

에러가 없으면 그대로 GitHub에 올려줘.
커밋 메시지는 [5회차 완성] 으로 하고, .env 는 올라가지 않게 확인해줘.
```

> `npm run build` 는 6회차에 Vercel이 하는 검사와 **같은 검사**입니다. 여기서 걸리면 배포가 멈추니 미리 걸러둡니다.

**아직 GitHub에 저장소가 없다면** (3회차에 안 올리신 경우)
```
이 프로젝트를 GitHub에 올려줘.
저장소 이름은 [my-site] 로, 비공개로 만들어줘.
.env 파일은 올라가지 않게 확인해줘.
```

### 6회차 · 배포

```
어제 이후로 바뀐 게 있으면 GitHub에 올려줘. 없으면 없다고만 알려줘.
```

5회차에 이미 올려두셨으면 이 단계는 건너뛰셔도 됩니다.

배포 자체는 Vercel 화면에서 클릭으로 합니다. AI가 할 일이 아니에요.

**배포 후 사이트에 데이터가 안 나오면**
```
Vercel에 배포했는데 사이트에서 데이터가 안 나와.
로컬에서는 잘 됐어.
환경 변수 이름이 뭐로 되어 있어야 하는지 알려줘.
```

## 에러가 났을 때 (제일 중요한 장)

### 3단계로 하세요

```
1단계 · AI에게 에러 메시지를 그대로 붙여넣는다   (3분)
2단계 · 안 풀리면 손을 든다                      (즉시)
3단계 · 옥탑방에서는 옆 사람에게 물어본다
```

혼자 30분씩 헤매지 않으셔도 됩니다. 그러라고 이 커뮤니티가 있어요.

### 에러 프롬프트 템플릿

```
이 명령어를 실행했는데 에러가 났어:
[내가 친 명령어]

에러 메시지 전체야:
[빨간 글씨 전부 복사해서 붙여넣기]

뭐가 문제인지, 뭘 확인해야 하는지 알려줘.
```

### 에러 메시지를 복사하는 법

터미널에서 빨간 글씨가 좌르르 뜨면, 처음 5줄만 복사해도 대부분 충분합니다.
드래그해서 `Ctrl + C` 로 복사됩니다.

### 같은 에러가 반복될 때

```
같은 에러가 세 번째야. 아까 알려준 방법대로 했는데 또 났어.
지금 상태를 다시 확인해줘. 뭘 놓쳤을까?
```

## AI끼리 팀 만들기 (역할 분담 프롬프트)

혼자서 기획, 디자인, 코딩 결정을 모두 하기 부담스러울 때가 있습니다.
그럴 때는 AI에게 역할을 나누어 스스로 대화하며 일하는 'AI 팀'을 만들어줄 수 있어요.

```
너는 이제 3명의 전문가로 구성된 AI 팀이야.

1. 수석 기획자 (사용자 경험과 페이지 구조 검토)
2. UI/UX 디자이너 (색상, 레이아웃, 세련된 모던 디자인)
3. Next.js 개발자 (안정적이고 간결한 코드 작성)

내가 [브런치 카페 리뷰 사이트를 만들고 싶어] 라고 말하면,
기획자가 구조를 정하고, 디자이너가 스타일을 제안하고, 개발자가 최선의 코드를 구현해줘.
셋이 서로 검수하고 합의한 뒤 최종 결과물만 나한테 보여줘.
```

이렇게 지시하면 AI가 단조로운 답 대신, 여러 각도로 검토된 결과물을 만들어줍니다.

## AI가 생각과 다르게 만들었을 때

### 되돌리기

```
방금 바꾼 걸 전부 되돌려줘. 그 전 상태로.
```

### 왜 그렇게 했는지 묻기

```
왜 그 파일을 새로 만들었어? 한 줄로만 설명해줘.
```

### 너무 많이 바꿨을 때

```
파일을 너무 많이 바꿨어.
앞으로는 파일을 고치기 전에 뭘 바꿀지 한 줄로 먼저 말해줘.
```

이 마지막 문장은 아예 `CLAUDE.md` 에 넣어두면 <mark>매번 안 말해도 됩니다.</mark>

## 이해 안 될 때 쓰는 프롬프트

넘어가도 되지만, 가끔 물어보면 실력이 늘어요.

```
방금 만든 파일들이 각각 무슨 역할인지 한 줄씩만 설명해줘.
전문 용어는 빼고.
```
