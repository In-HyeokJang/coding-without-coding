## 이게 뭔가요

AI에게 "예쁘게 해줘" 라고 하면 매번 다른 게 나옵니다. 어제는 파란색, 오늘은 보라색, 카드 모서리도 제각각.

**기준이 없어서 그래요.**

`DESIGN.md` 는 그 기준을 적어둔 파일 한 장입니다. 색은 뭘 쓰고, 글씨 크기는 어떻게 가고, 간격은 얼마나 띄우는지가 정리돼 있어요.

이 파일을 프로젝트에 넣어두고 <mark>"DESIGN.md 대로 해줘"</mark> 라고 하면, AI가 그 기준을 지켜서 만듭니다.

:::note[좋은 소식이 하나 있어요]
이런 기준을 **직접 만들 필요가 없습니다.**

유명한 서비스들의 디자인 규칙을 이미 마크다운으로 정리해서 공개해둔 곳이 있거든요.
거기서 마음에 드는 걸 하나 골라 가져다 쓰면 됩니다.
:::

## 템플릿을 통째로 가져오는 것과 뭐가 다른가요

이게 이 방식의 핵심입니다.

**남의 템플릿을 통째로 가져오면**

- 남이 만든 **코드와 화면 구조**가 통째로 따라와요
- 내 페이지 구조가 템플릿 것으로 바뀝니다
- 4회차에 붙인 기능이 깨질 수 있어요
- 고치려면 코드를 읽을 줄 알아야 하고요

**`DESIGN.md` 로 가져오면**

- **색·글씨·간격 규칙**만 가져와요
- 내 페이지 구조는 그대로 남아요
- 기능도 안 건드립니다
- 고치고 싶으면 말로 시키시면 돼요

**내 구조는 그대로 두고, 겉모습만 올려주는 방식**이에요.

그래서 2회차에 정한 페이지 목록도, 4회차에 붙인 기능도 그대로 살아 있습니다.

## 방법 1 · GitHub에서 복사하기 (이걸 추천합니다)

명령어를 안 써도 되고, 무엇을 가져오는지 눈으로 보면서 할 수 있어요.

### ① 저장소 열기

브라우저에서 [github.com/VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md) 를 엽니다.

### ② `design-md` 폴더를 클릭해서 들어가기

:::caution[여는 순간 브랜드 이름이 안 보여요]
첫 화면에는 폴더가 두어 개, 파일이 몇 개뿐입니다. 브랜드 이름은 안 보여요.

<mark>`design-md` 라고 적힌 폴더를 한 번 클릭해서 들어가셔야</mark> 그 목록이 나옵니다.
:::

들어가면 브랜드 이름 폴더가 쭉 나와요. **74곳이에요.**

### ③ 브랜드 폴더에 들어가서 `DESIGN.md` 열기

마음에 드는 브랜드 폴더를 클릭하고, 그 안의 **`DESIGN.md`** 를 한 번 더 눌러주세요.

**클릭이 세 번이에요.** `design-md` → `브랜드 이름` → `DESIGN.md` 순서예요.

### ④ 파일 내용 복사하기

파일을 클릭하면 내용이 보입니다.

화면 **오른쪽 위**에 버튼이 몇 개 있어요. 그중 **복사 버튼**(네모 두 개가 겹친 모양)을 누르시면 전체가 복사됩니다.

> 버튼을 못 찾으시겠으면 **Raw** 버튼을 누르고, 그 화면에서 `Ctrl + A` → `Ctrl + C` 하셔도 똑같아요.

### ⑤ 내 프로젝트에 파일로 만들기

Claude 채팅창에 아래를 붙여넣으세요. 마지막 줄 자리에 방금 복사한 걸 붙이시면 됩니다.

```
프로젝트 맨 위에 DESIGN.md 라는 파일을 만들고,
아래 내용을 그대로 넣어줘. 내용은 고치지 말고 그대로.

[여기에 복사한 것 붙여넣기]
```

**확인:** VSCode 왼쪽 파일 목록에 `DESIGN.md` 가 보이면 성공입니다.

## 방법 2 · 명령어 한 줄로

같은 팀이 만든 도구가 있어요. 복사·붙여넣기 없이 한 줄로 받아집니다.

**어떤 게 있는지 목록 보기**

```
npx getdesign list
```

**골라서 받기**

```
npx getdesign add claude
```

`claude` 자리에 폴더 이름을 넣으시면 됩니다. `apple`, `spotify` 처럼요.

받고 나면 프로젝트 맨 위에 `DESIGN.md` 가 생겨 있어요. 방법 1과 결과가 똑같습니다.

:::note[2회차부터 터미널은 안 쓰기로 했었죠]
맞아요. 그래서 **이 방법은 안 하셔도 됩니다.** 방법 1과 결과가 똑같거든요.

굳이 해보고 싶으시면, VSCode 위쪽 메뉴에서 **터미널 → 새 터미널**을 누르면 아래에 까만 창이 열려요. 거기에 치시면 됩니다.

**아니면 이렇게 시키셔도 돼요.** 채팅창에 그대로 넣으시면 AI가 대신 쳐줍니다.

```
npx getdesign add claude 를 실행해줘.
```
:::

## 이제 어떻게 쓰나요

파일만 만들어두면 AI가 알아서 보지는 않습니다. **한 번 말해줘야 해요.**

### ⓪ 먼저 뭘 바꿀 건지 물어보기

바로 고치게 하지 마시고, **먼저 보고를 받으세요.** 이 한 단계가 사고를 많이 막아줍니다.

```
DESIGN.md 를 읽고, 지금 홈 화면과 비교해줘.

- 뭐가 다른지 5개만 목록으로
- 어느 파일을 고치게 되는지도 같이

아직 고치지는 마.
```

무슨 말인지 잘 모르겠어도 괜찮아요. **"아, 색이랑 글씨 크기를 바꾸겠구나" 정도만 보시면 됩니다.**

### ① 한 페이지만 적용하기

```
좋아. 이제 그 기준대로 홈 화면만 바꿔줘.

- 화면 구조는 바꾸지 마
- 기능도 건드리지 마
- 색, 글씨 크기, 간격만

다 하고 나면 뭘 바꿨는지 알려줘.
```

**한 페이지씩** 이 중요합니다. 전부 한꺼번에 시키면 어디가 어떻게 바뀐 건지 알 수 없어요.

### ② 눈으로 확인하기

브라우저를 새로고침하고 **직접 보세요.** 이때 세 가지만 보시면 됩니다.

- 글씨가 읽히나요
- 버튼이 버튼처럼 보이나요
- 화면이 답답하거나 휑하지 않나요

### ③ 마음에 들면 다음 페이지로

```
좋아. 이제 [상세] 페이지도 같은 기준으로 해줘.
```

### 마음에 안 들면

```
방금 바꾼 걸 되돌려줘. 그 전 상태로.
```

말로 설명하기 어려우면 **어디인지만 알려주셔도** 됩니다.

```

DESIGN.md 기준에 더 맞게 다시 잡아줘. 다른 데는 두고.
```
:::

## AI가 실제로 뭘 고치나요

궁금하실 것 같아 적어둡니다. **몰라도 쓰는 데 지장은 없어요.**

우리 프로젝트는 **Tailwind CSS**(색과 간격을 짧은 이름으로 적어두는 방식)를 씁니다. 3회차에 프로젝트를 만들 때 같이 깔렸어요.

그래서 보통 두 군데가 바뀝니다.

| 어디 | 뭐가 바뀌나 |
|---|---|
| `globals.css` | 색·글씨·간격의 **기준값**이 여기 등록됩니다 |
| 각 화면 파일 | 그 기준을 **실제로 쓰도록** 글자가 바뀝니다 |

그래서 "색을 바꿔줘" 라고 하면 파일 두 개 이상이 같이 바뀌는 게 정상이에요. 놀라지 않으셔도 됩니다.

## CLAUDE.md 에 걸어두기

디자인 작업을 여러 번 하실 거라면, 매번 "DESIGN.md 읽고" 라고 말하기 번거롭죠.

`CLAUDE.md` 에 이 두 줄을 넣어두시면 됩니다.

```
## 디자인
- 색·글씨·간격을 바꿀 때는 DESIGN.md 를 먼저 읽고 그 규칙을 따른다.
- 구조나 기능은 DESIGN.md 와 상관없이 건드리지 않는다.
```

넣는 건 이렇게 시키시면 돼요.

```
CLAUDE.md 맨 아래에 "## 디자인" 항목을 만들고 이 두 줄을 넣어줘.

[위 두 줄 붙여넣기]
```

:::caution[토큰이 생각보다 많이 듭니다]
`DESIGN.md` 는 보통 **꽤 긴 파일**입니다. 수백 줄짜리도 있어요.

`CLAUDE.md` 에 "항상 읽어라" 라고 걸어두면 **대화할 때마다 그 긴 파일을 다시 읽습니다.**

그래서 위 규칙을 `색·글씨·간격을 바꿀 때는` 이라고 조건을 붙여 적었어요. 디자인 작업이 아닐 때는 안 읽도록요.

**디자인을 다 잡고 나면** 그 두 줄을 지우셔도 됩니다. 이미 코드에 반영돼 있으니까요.
:::

:::caution[브랜드 이름과 로고는 쓰지 마세요]
가져오는 건 **색과 간격 같은 규칙**이지, 그 브랜드가 되는 게 아닙니다.

남의 회사 이름이나 로고를 내 사이트에 넣으면 안 돼요. 참고만 하시는 겁니다.
:::

## 자주 나오는 질문

**Q. `DESIGN.md` 를 만들었는데 AI가 안 보는 것 같아요.**
`CLAUDE.md` 와 달리 자동으로 읽히지 않습니다. 프롬프트에 `DESIGN.md 를 읽고` 를 넣어주세요.

**Q. 적용했는데 화면이 거의 그대로예요.**
AI가 파일만 읽고 실제로는 안 고친 경우예요. 이렇게 되물어보세요.

```
방금 어느 파일의 어느 부분을 바꿨는지 알려줘.
안 바꿨으면 안 바꿨다고 말해줘.
```

**Q. 적용했더니 화면이 깨졌어요.**
바로 되돌리시면 됩니다. `방금 바꾼 걸 되돌려줘` 한 줄이면 돼요.

되돌린 다음에는 **한 페이지가 아니라 한 부분씩** 시켜보세요. "홈 화면 전체" 대신 "홈 화면의 제목 부분만" 처럼요.

**Q. 색이 계속 마음에 안 들어요.**
브랜드를 바꿔보는 게 빠를 때가 많아요. 규칙 하나를 붙들고 고치는 것보다, `DESIGN.md` 를 다른 것으로 갈아끼우는 편이 낫습니다.

**Q. 두 개를 섞어 쓰고 싶어요.**
권하지 않습니다. 기준이 두 개면 기준이 없는 것과 같아져요. 하나로 가시고, 마음에 안 들면 통째로 바꾸세요.

**Q. 바꾸고 싶으면 어떻게 하나요?**
새 `DESIGN.md` 로 파일 내용을 갈아끼우고, 다시 "DESIGN.md 대로 해줘" 라고 하시면 됩니다.

**Q. Codex(ChatGPT)를 써도 되나요?**
됩니다. `DESIGN.md` 는 그냥 마크다운 파일이라 도구를 가리지 않아요. `CLAUDE.md` 자리에 `AGENTS.md` 를 쓰시면 됩니다.

**Q. frontend-design 스킬이랑 뭐가 다른가요?**
스킬은 "AI가 만든 티를 줄여줘" 에 가깝고, `DESIGN.md` 는 **정해진 기준을 따르게** 하는 겁니다. 둘 다 쓰셔도 되지만, 하나씩 해보시는 게 차이를 알기 좋아요.
