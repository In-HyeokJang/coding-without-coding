## 오늘 하는 것 5단계

### 1단계 · GitHub 푸시 + Vercel 연결 (20분)

어제 이미 GitHub에 올려두셨죠. **어제 이후로 고친 게 없으면 이 단계는 건너뛰셔도 됩니다.**

집에서 뭔가 더 만지셨다면 이것만 한 번.

```
어제 이후로 바뀐 게 있으면 GitHub에 올려줘. 없으면 없다고만 알려줘.
```

그다음은 **Vercel 화면에서 클릭으로** 진행합니다. AI가 할 일이 아니에요.

1. vercel.com 로그인
2. **Add New → Project**
3. 내 GitHub 저장소를 고르고 **Import**

대부분 클릭만 하면 됩니다. 여기까진 어렵지 않아요.

:::danger[여기서 멈춰주세요]
Import 를 누르면 설정 화면이 뜹니다. 그 화면 아래쪽에 **`Deploy` 버튼이 벌써 보여요.** <mark>아직 누르지 마세요.</mark>

지금 누르면 열쇠가 없는 채로 올라갑니다.
2단계에서 열쇠를 먼저 넣고, 3단계에서 다 같이 카운트다운해서 눌러요.
:::

---

### 2단계 · 환경 변수 등록 (30분) — 오늘의 진짜 벽

**이게 뭔가요**
4회차에 복사해둔 Supabase 키 2개를 **Vercel에도 등록하는 것**입니다.

**왜 필요한가**
지금까지 그 키는 내 노트북 `.env` 파일에만 있었어요.
그런데 사이트는 이제 Vercel 서버에서 돌아갑니다.

그 서버도 열쇠가 있어야 창고에 접속할 수 있겠죠.

**어디에**
**방금 그 화면에서 그대로** 아래로 내리시면 됩니다. 다른 데로 가지 않으셔도 돼요.

`Environment Variables` 라고 적힌 자리가 나옵니다. 접혀 있으면 한 번 눌러서 펴주세요.

**뭘 넣나**
`이름` 칸과 `값` 칸이 있습니다. **두 줄**을 넣게 돼요.

| 이름 칸 | 값 칸 |
|---|---|
| 내 `.env` 에 적힌 이름 그대로 | Supabase의 Project URL |
| 내 `.env` 에 적힌 이름 그대로 | Supabase의 publishable key |

**칸이 한 줄만 보이는데요?**
첫 줄을 채우고 나면 아래에 **`Add Another`** 또는 **`+`** 처럼 한 줄 더 만드는 버튼이 있어요. 그걸 눌러서 두 번째 줄을 만드시면 됩니다.

안 보이시면 손 들어주세요. 화면 생김새가 조금씩 달라지는 자리예요.

---

### 내 이름이 뭐였더라

4회차 끝에 `CLAUDE.md` 에 적어두셨으면 그걸 그대로 쓰시면 됩니다.

**안 적어두셨어도 30초면 찾아요.** 채팅창에 이렇게 물어보세요.

```
.env 파일에 있는 변수 이름과 값을 그대로 보여줘.
Vercel에 옮겨 적어야 해.
```

나온 걸 **복사해서 그대로** 넣으시면 됩니다. 직접 타이핑하지 마세요.

:::caution[오늘 에러의 90%가 여기서 납니다]
**① 이름을 손으로 쳐서 한 글자가 다름**
`NEXT_PUBLIC_SUPABASE_URL` 에서 밑줄 하나, 대소문자 하나만 달라도 안 됩니다. <mark>복사해서 붙여넣기로만 하세요.</mark>

**② 두 줄 중 하나만 넣음**
주소와 열쇠, **둘 다** 있어야 합니다. 하나만 넣으면 화면이 비어 보여요.

**③ 값을 복사할 때 앞뒤 공백이 딸려옴**
붙여넣고 나서 커서를 맨 끝으로 옮겨 확인하세요.
:::

:::note[값을 붙여넣는 건 괜찮습니다]
Vercel의 이 칸은 **밖으로 안 새는 자리**예요. 원래 여기에 넣으라고 있는 칸입니다.
:::

---

**두 줄을 다 넣으셨으면 여기서 멈춥니다.**

`Deploy` 버튼은 아직 누르지 않으셔도 돼요. 6명이 다 준비될 때까지 같이 기다립니다.
다 되신 분은 손을 들어주시면 돼요.

---

### 3단계 · 3, 2, 1 동시 배포

**6명 다 Deploy 버튼 앞에서 대기합니다.**

아직 안 되신 분이 있으면 다 같이 기다려요. 타스가 옆에서 같이 뚫습니다.

그리고 카운트다운.

```
3 ... 2 ... 1 ...
```

**동시에 클릭.**

---

**그다음 1~3분.**

빌드 로그가 좌르르 흘러갑니다. 6명이 동시에 화면을 쳐다봅니다.

그리고 초록색으로 **`Ready`** 가 뜨면서 —

**주소가 생깁니다.**

---

### 4단계 · 사이트 열어보기 (안 나오면 여기서 고칩니다)

**생긴 주소를 눌러서 직접 들어가보세요.**

화면이 뜨고 데이터가 나오면 끝입니다. 5단계로 가시면 돼요.

**빈 화면이거나 데이터가 안 나온다면** 열쇠 두 줄 중 뭔가가 어긋난 거예요. 오늘 제일 흔한 일이라 놀라지 않으셔도 됩니다.

이제는 프로젝트가 만들어졌으니 **Settings 로 들어갈 수 있습니다.**

1. Vercel 프로젝트 → **Settings → Environment Variables**
2. 이름과 값을 다시 확인하고 고칩니다

:::caution[고치기만 하면 안 바뀝니다. 한 번 더 올려야 해요]
Vercel은 **이미 올라간 사이트에는 새 값을 적용하지 않습니다.** 다시 올려야 바뀌어요.

1. **Deployments** 탭으로 갑니다
2. 맨 위 배포 오른쪽 **`...`** 을 누릅니다
3. **`Redeploy`** 를 누릅니다

이걸 안 하면 값을 아무리 고쳐도 화면은 그대로입니다.

다시 올라가는 데 1~3분 걸려요. 끝나면 **주소를 한 번 더 열어서** 이번엔 나오는지 보시면 됩니다.
:::

**막혔을 때 프롬프트**
```
Vercel에 배포했는데 사이트에서 데이터가 안 나와.
로컬에서는 잘 됐어.
환경 변수 이름이 뭐로 되어 있어야 하는지 알려줘.
```

### 5단계 · 서로 폰으로 접속

**폰을 꺼내주세요.**

옆 사람의 URL을 자기 폰에 입력해주세요.

**내가 만든 사이트가 남의 폰에서 열립니다.**

내 노트북이 아니라, 남의 손 안에 있는 기계에서요. 3주 전엔 상상도 못 했던 일이에요.

## 배포가 안 되면요?

**괜찮습니다. 오늘 안에 같이 끝냅니다.**

- 카운트다운은 다 같이 합니다. 실패해도 같이 눌러요
- 폰으로 접속하는 시간에 타스가 옆에 붙습니다
- 그래도 안 되면 회차 끝나고 남아서 같이 뚫습니다
- **타임캡슐은 배포와 상관없이 엽니다.** 오늘 다 같이 열어봐요

**혼자 남겨지지 않습니다.**

- URL은 그대로예요
