## 오늘 미리 알아두면 좋은 것

**시즌 마지막이에요.**

지금까지 `localhost:3000` 은 내 노트북에서만 열렸어요.
오늘 그게 **누구나 열 수 있는 주소**가 돼요.

```
https://내프로젝트이름.vercel.app
```

그리고 **6명이 같은 시각에 다 같이 배포해요.**

---

## 오늘 하는 것 5단계

### 1단계 · GitHub 푸시 + Vercel 연결 (20분)

먼저 GitHub에 오늘 코드가 올라가 있는지만 확인할게요. 이것만 시켜보시면 돼요.

```
지금 상태를 GitHub에 올려줘.
이미 올라가 있으면 그렇다고만 알려줘.
.env 는 올라가지 않게 확인해줘.
```

**어제 못 올리셨어도 괜찮아요.** 이 한 줄이면 지금 올라갑니다.

그다음은 **Vercel 화면에서 클릭으로** 해요. 여기는 AI가 대신 못 하는 부분이에요.

1. vercel.com 로그인
2. **Add New(새로 만들기) → Project(프로젝트)**
3. 내 GitHub 저장소를 고르고 **Import(가져오기)**

여기까지는 클릭만 하시면 돼요.

:::danger[여기서 멈춰주세요]
Import 를 누르면 설정 화면이 뜹니다. 그 화면 아래쪽에 **`Deploy`(올리기) 버튼이 벌써 보여요.** <mark>아직 누르지 마세요.</mark>

지금 누르면 열쇠가 없는 채로 올라갑니다.
2단계에서 열쇠를 먼저 넣고, 3단계에서 다 같이 카운트다운해서 눌러요.
:::

---

### 2단계 · 환경 변수 등록 (30분)

**이게 뭔가요**
4회차에 복사해둔 Supabase 키 2개를 **Vercel에도 등록하는 것**입니다.

**왜 필요한가**
지금까지 그 키는 내 노트북 `.env` 파일에만 있었어요.
그런데 사이트는 이제 Vercel 서버에서 돌아갑니다.

그 서버도 열쇠가 있어야 창고에 접속할 수 있겠죠.

**어디에**
**방금 그 화면에서 그대로** 아래로 내리시면 됩니다. 다른 데로 가지 않으셔도 돼요.

`Environment Variables` 라고 적힌 자리가 나옵니다. 접혀 있으면 한 번 눌러서 펴주세요.

**뭘 넣나**
`이름` 칸과 `값` 칸이 있어요. **두 줄**을 넣게 됩니다.

| 이름 칸 | 값 칸 |
|---|---|
| 내 `.env` 에 적힌 이름 그대로 | Supabase의 Project URL |
| 내 `.env` 에 적힌 이름 그대로 | Supabase의 publishable key |

**칸이 한 줄만 보이는데요?**
첫 줄을 채우고 나면 아래에 **`Add Another`** 또는 **`+`** 처럼 한 줄 더 만드는 버튼이 있어요. 그걸 눌러서 두 번째 줄을 만드시면 됩니다.

안 보이시면 손 들어주세요. 화면 생김새가 조금씩 달라지는 자리예요.

---

### 내 이름이 뭐였더라

4회차 끝에 `CLAUDE.md` 에 적어두셨으면 그걸 그대로 쓰시면 됩니다.

**안 적어두셨어도 30초면 찾아요.** 채팅창에 이렇게 물어보세요.

```
.env 파일에 있는 변수 이름과 값을 그대로 보여줘.
Vercel에 옮겨 적어야 해.
```

나온 걸 **복사해서 그대로** 넣으시면 돼요. 직접 타이핑하지 마세요.

:::caution[여기서 잘 안 되면 보통 이 셋 중 하나예요]
**① 이름을 손으로 쳐서 한 글자가 다를 때**
`NEXT_PUBLIC_SUPABASE_URL` 에서 밑줄 하나, 대소문자 하나만 달라도 안 돼요. <mark>복사해서 붙여넣기로만 하세요.</mark>

**② 두 줄 중 하나만 넣었을 때**
주소와 열쇠, **둘 다** 있어야 해요. 하나만 있으면 화면이 비어 보여요.

**③ 값을 복사할 때 앞뒤 공백이 딸려왔을 때**
붙여넣고 나서 커서를 맨 끝으로 옮겨 확인해보시면 돼요.

셋 다 흔한 일이라 걸리셔도 놀라지 않으셔도 돼요.
:::

:::note[값을 붙여넣는 건 괜찮아요]
Vercel의 이 칸은 **밖으로 안 새는 자리**예요. 원래 여기에 넣으라고 있는 칸이거든요.
:::

---

**두 줄을 다 넣으셨으면 여기서 잠깐 멈춰요.**

`Deploy` 버튼은 아직 누르지 않으셔도 돼요. 6명이 다 준비될 때까지 같이 기다릴 거예요.

**이 시간에 타스가 한 분씩 화면을 봐드릴게요.** 잘 들어갔는지 같이 확인하면 마음이 놓이거든요.

---

### 3단계 · 3, 2, 1 다 같이 배포

**6명 다 Deploy 버튼 앞에 모여요.**

아직 준비가 안 되신 분이 있으면 다 같이 기다려요. 타스가 옆에서 같이 봐드릴게요.

**기다리는 게 하나도 미안한 일이 아니에요.** 오늘은 같이 누르는 게 목적이거든요.

그리고 카운트다운.

```
3 ... 2 ... 1 ...
```

**동시에 클릭.**

---

**그다음 1~3분.**

글씨가 좌르르 흘러가요. 컴퓨터가 지금 무슨 일을 하고 있는지 적어 보여주는 거예요. 읽지 않으셔도 괜찮아요.

그러다 초록색으로 **`Ready`**(다 됐다는 뜻이에요) 가 뜨면서 —

**내 사이트 주소가 생겨요.**

빨간 글씨가 뜬 분도 계실 거예요. 그것도 오늘 있는 일이라 바로 같이 봐드릴게요.

---

### 4단계 · 사이트 열어보기 (안 나와도 여기서 같이 고쳐요)

**생긴 주소를 눌러서 직접 들어가보세요.**

화면이 뜨고 데이터가 나오면 다 된 거예요. 5단계로 가시면 돼요.

**빈 화면이거나 데이터가 안 나와도 괜찮아요.** 열쇠 두 줄 중 하나가 살짝 어긋난 것뿐이거든요.

오늘 제일 흔한 일이에요.

이제 프로젝트가 만들어졌으니 **Settings(설정) 로 들어갈 수 있어요.**

1. Vercel 프로젝트 → **Settings(설정) → Environment Variables(환경 변수)**
2. 이름과 값을 다시 보고 고쳐주세요

:::caution[고친 다음 한 번 더 올려야 바뀌어요]
Vercel은 **이미 올라간 사이트에 새 값을 자동으로 적용하지 않아요.** 다시 한 번 올려야 반영됩니다.

1. **Deployments(올린 기록)** 탭으로 가요
2. 맨 위에 있는 것 오른쪽 **`...`** 을 눌러요
3. **`Redeploy`**(다시 올리기) 를 눌러요

다시 올라가는 데 1~3분 걸려요. 끝나면 **주소를 한 번 더 열어서** 이번엔 나오는지 보시면 돼요.
:::

**막혔을 때 프롬프트**
```
Vercel에 배포했는데 사이트에서 데이터가 안 나와.
로컬에서는 잘 됐어.
환경 변수 이름이 뭐로 되어 있어야 하는지 알려줘.
```

### 5단계 · 서로 폰으로 접속

**폰을 꺼내주세요.**

옆 사람의 URL을 자기 폰에 입력해주세요.

**내가 만든 사이트가 남의 폰에서 열립니다.**

내 노트북이 아니라, 남의 손 안에 있는 기계에서요. 3주 전엔 상상도 못 했던 일이에요.

## 오늘 배포가 안 되면요?

**괜찮아요. 오늘 안에 같이 마무리해요.**

- 카운트다운은 다 같이 해요. 안 돼도 같이 눌러요
- 폰으로 접속하는 시간에 타스가 옆에 앉아서 같이 봐드려요
- 그래도 안 되면 회차 끝나고 남아서 끝까지 같이 봐드릴게요
- **타임캡슐은 배포와 상관없이 열어요.** 오늘 다 같이 열어봅니다

**혼자 남겨두지 않을게요.**

---

## 시즌이 끝나고

**여러분 사이트는 계속 살아 있어요.**

- 언제든 다듬을 수 있어요. Claude Code에게 시키시면 돼요
- 고치고 GitHub에 올리면 Vercel이 알아서 다시 올려줘요
- 주소는 그대로예요

**3주 전에 없던 것이 지금 있어요.**

오늘 배포까지 못 가신 분도 마찬가지예요. 3주 전에는 폴더 하나 만드는 것도 못 하셨잖아요.

**시작해본 사람과 안 해본 사람의 차이는 여기서 갈려요.** 여러분은 이미 시작하셨어요.
