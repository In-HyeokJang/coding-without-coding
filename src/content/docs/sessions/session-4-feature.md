## 오늘 새로 준비하는 것 · Supabase

**Supabase가 뭔가요?**
데이터를 저장하는 창고입니다.

지금 화면은 예쁘기만 하고 아무것도 기억하지 못합니다. 리뷰를 써도 새로고침하면 사라져요.
Supabase가 그걸 대신 보관해줍니다.

### 어디까지 하나

1. **가입 & 프로젝트 확인** — 지난 시간에 가입해둔 supabase.com에 로그인
2. **테이블 하나 만들기** — 화면에서 클릭으로. **SQL 안 씁니다**
3. **API 키 2개 복사해두기** ← 이거 중요

### API 키가 뭔가요

내 데이터 창고의 **주소와 열쇠**입니다.

| 이름 | 뭔가 |
|---|---|
| **Project URL** | 창고 주소 |
| **publishable key** (예전 이름 `anon`) | 손님용 열쇠 — 내 사이트에 넣고 쓰는 것 |

이 두 개를 AI에게 주면 나머지는 AI가 코드에 넣어줍니다.

:::danger[`secret` 이라고 적힌 키는 절대 복사하지 마세요]
같은 화면에 열쇠가 **두 종류** 있습니다. 이름만 잘 보시면 돼요.

| 복사할 것 | 절대 안 되는 것 |
|---|---|
| `sb_publishable_...` | `sb_secret_...` |
| (예전 이름 `anon`) | (예전 이름 `service_role`) |

**`secret` · `service_role` 쪽은 주인용 마스터 키예요.** 이게 사이트에 들어가면 잠금장치를 전부 무시하고 남이 내 데이터를 통째로 지울 수 있습니다.

헷갈리시면 복사하기 전에 손 들어주세요. 30초면 같이 확인해드려요.
:::

:::note[`publishable` 키는 채팅창에 붙여넣어도 괜찮아요]
이 열쇠는 **원래 공개되는 용도**입니다. `.env` 에 넣어도 결국 내 사이트 코드에 실려서 나가요.

그래서 진짜 잠금장치는 키가 아니라 **Supabase 쪽 설정**입니다. 바로 아래에서 봅니다.

`.env` 에 넣는 건 그것대로 필요해요. AI에게 키를 줄 때 **"이 키를 .env 파일에 넣어줘"** 를 꼭 같이 말하세요.
:::

### 테이블을 만들면 잠겨 있습니다 (중요)

Supabase는 새로 만든 테이블에 **자물쇠를 걸어둡니다.** 아무나 내 데이터를 읽고 지우지 못하게요.

그래서 오늘 연결하면 십중팔구 **"저장은 눌리는데 아무 일도 안 일어나는"** 상황을 만납니다. <mark>고장이 아니라 자물쇠예요.</mark>

**푸는 법** — Supabase 화면에서 "이 테이블은 누구나 읽고 쓸 수 있다" 는 규칙(정책)을 하나 만들어주면 됩니다. 막히시면 AI에게 이렇게 물어보세요.

```
Supabase 테이블에 저장이 안 돼. RLS 정책이 없어서 그런 것 같아.

테이블 이름은 [reviews] 야.
지금은 연습용이니까 누구나 읽고 쓸 수 있게 하고 싶어.

Supabase 화면에서 어디를 눌러야 하는지 순서대로 알려줘.
```

:::caution[이 설정은 "연습용" 이라는 뜻이에요]
누구나 읽고 쓸 수 있게 열어두는 겁니다. 커뮤니티에서 만드는 연습 사이트라 괜찮아요.

**남에게 오래 보여줄 사이트라면** 나중에 이 부분을 조여야 합니다. 그때 AI에게 `이 테이블 정책을 안전하게 다시 짜줘` 라고 하시면 돼요.
:::

### 우리가 안 하는 것

DB 설계, 정규화, SQL, 인덱스 — 안 합니다.
`이름`, `내용`, `날짜` 정도의 칸을 클릭으로 만들면 끝이에요.

## 오늘 하는 것 3단계

### 1단계 · 먼저 폼만 만들기 (30분) — 여기까진 6명 다 성공합니다

Supabase 없이 화면에서만 되는 걸 먼저 만듭니다.

**대괄호 안만 내 것으로 바꾸시면 됩니다.**

```
홈 화면에 [리뷰]를 입력하는 폼을 추가해줘.
입력 칸: [카페 이름], [별점], [한 줄 평]
저장 버튼을 누르면 아래 목록에 바로 나타나면 돼.

아직 데이터베이스는 연결하지 마. 화면에서만 되면 돼.
```

> 산책 코스 사이트라면 `[코스 이름], [난이도], [한 줄 소감]` 처럼요.
> 뭘 넣을지 모르겠으면 `내 사이트에 맞는 입력 칸을 3개만 정해줘` 라고 먼저 물어보세요.

**결과:** 입력하고 저장하면 목록에 뜹니다. 새로고침하면 사라져요. 괜찮습니다.

오늘의 최소 결과물이 이겁니다. 여기까지만 하셔도 오늘 온 보람이 있어요.

---

### 2단계 · Supabase 연결 시도 (30분) — 여기서부터 갈립니다

```
이제 Supabase에 연결해줘.

내 Supabase 정보야:
Project URL: [붙여넣기]
publishable key: [붙여넣기]

테이블 이름은 [reviews] 이고, 칸은 [name, rating, comment] 야.

저장 버튼을 누르면 Supabase에 들어가고,
새로고침해도 목록이 그대로 남아 있게 해줘.

키는 .env 파일에 넣어서 코드에 직접 안 보이게 해줘.
```

> 테이블·칸 이름은 아까 Supabase 화면에서 직접 만드신 그 이름을 그대로 적으시면 됩니다.

**여기서 첫 에러를 만나게 됩니다.**

지금까지는 AI가 뽑아주면 됐어요. 오늘은 뽑아줘도 한 번에 안 될 수 있습니다.
이 순간이 오늘의 진짜 시작이에요.

### 에러가 나면 이 순서로

혼자 30분씩 헤매지 않으셔도 됩니다.

1. **AI에게 에러 메시지를 그대로 붙여넣기** (3분)
2. 안 풀리면 **손 들기** (즉시)
3. **옆 사람에게 물어보기**

**오늘 제일 많이 나오는 것부터**

| 이럴 때 | 뭐가 문제인가 |
|---|---|
| 저장은 눌리는데 아무 일도 안 일어남 | **자물쇠(RLS)** 일 확률이 높아요. 위 [테이블을 만들면 잠겨 있습니다](#테이블을-만들면-잠겨-있습니다-중요) 의 프롬프트를 쓰세요 |
| 목록이 계속 비어 있음 | 같은 자물쇠거나, 테이블·칸 이름이 다를 때 |
| `Invalid API key` 같은 글씨 | 키를 복사할 때 앞뒤가 잘렸을 수 있어요. 다시 복사 |

**에러 프롬프트**

```
Supabase를 연결했는데 에러가 나:

[에러 메시지 붙여넣기]

지금 화면에서는 [저장 버튼을 눌러도 아무 일도 안 일어나].
뭘 확인해야 해?
```

**같은 에러가 세 번째라면**

```
같은 에러가 세 번째야. 아까 알려준 방법대로 했는데 또 났어.
지금 상태를 처음부터 다시 확인해줘. 뭘 놓쳤을까?
```

오늘 어렵게 만든 것을 GitHub에 보관해 둡니다. 3회차에 한 번 해보셨으니 오늘은 금방이에요.

**어디까지 왔든 올리시면 됩니다.** 폼까지만 됐어도 그 상태로 올려두는 게 맞아요.


:::caution[.env 가 올라가지 않았는지 꼭 확인하세요]
`.env` 안에는 Supabase 열쇠가 들어 있습니다. GitHub에 올라가면 남이 내 데이터 창고를 열 수 있어요.

위 프롬프트에 이미 넣어뒀지만, 한 번 더 물어보셔도 좋습니다.

```
방금 올린 것 중에 .env 파일이 들어갔는지 확인해줘.
```
:::

### 하나만 더 · `.env` 에 적힌 이름 베껴두기 (2분)

**6회차 배포 때 이게 없으면 거기서 막힙니다.** 지금 30초면 끝나요.

```
.env 파일에 있는 변수 이름 2개를 보여줘. 값은 빼고 이름만.
```

`NEXT_PUBLIC_...` 으로 시작하는 이름 두 줄이 나옵니다. 그걸 **`CLAUDE.md` 맨 아래에 그대로 붙여두세요.**

```markdown
## 배포할 때 쓸 이름
NEXT_PUBLIC_...
NEXT_PUBLIC_...
```

:::caution[이름만 적으세요. 값(열쇠)은 적지 마세요]
`CLAUDE.md` 는 GitHub에 올라가는 파일이에요. **이름만** 적으면 안전하고, 값까지 적으면 `.env` 에 숨긴 의미가 없어집니다.
:::

6회차에 Vercel 화면에 이 이름을 **글자 하나까지 똑같이** 옮겨 적게 됩니다. 대소문자 하나만 달라도 사이트가 비어 보여요.

:::tip[6일 동안 천천히 하시면 돼요]
집에서 막히셔도 괜찮습니다. **어디서 막혔는지만 적어두고** 5회차에 가져오세요.

혼자 오래 붙잡고 계시는 것보다, 그게 훨씬 빨리 풀립니다.
