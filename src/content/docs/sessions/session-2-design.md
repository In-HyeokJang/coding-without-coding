## 오늘 미리 알아두면 좋은 것

어제 폴더는 만들었는데, **뭘 만들어야 할지는 아직 모릅니다.**

"카페 리뷰 사이트요" 정도로는 AI가 화면을 못 만들어요.
**"홈에는 이거, 상세에는 이거"** 까지 정해야 3회차에 화면이 뜹니다.

오늘 그걸 정합니다. **코드는 안 씁니다.**

---

## 오기 전에

- [ ] 노트북 (1회차에 설치한 그대로)
- [ ] **참조 사이트 하나 떠올려 오기** (필수 X, 있으면 시간 절약)
- [ ] 메모할 곳 (노션, 메모장, 아무거나)

**참조 사이트가 뭔가요?**
내가 만들고 싶은 것과 비슷한 **실제로 있는 사이트** 하나.

> 예: 브런치 카페 리뷰 사이트를 만들고 싶다 → 실제 맛집 리뷰 사이트 하나

똑같이 만들려는 게 아닙니다. **"여기 이 부분이 나한테 필요해요"** 를 짚기 위해서예요.

## 오늘의 규칙

시작하기 전에 이것부터. **오늘은 이 4개만 지키면 됩니다.**

### 1. 한 번에 하나만 물어보기 ← 오늘의 핵심

이게 오늘 제일 중요합니다.

**이렇게 하지 마세요**
> 페이지 목록 뽑아주고 색깔도 정해주고 어떤 기능 넣을지도 알려주고 파일도 만들어줘

**이렇게 하세요**
> 페이지 목록을 뽑아줘.

답이 오면 → 읽고 → **그다음 하나**를 물어봅니다.

**왜 이렇게 해야 하나요?**

| 한꺼번에 물어보면 | 하나씩 물어보면 |
|---|---|
| 여덟 개는 대충, 두 개는 틀립니다 | 하나하나 제대로 나옵니다 |
| **뭐가 틀렸는지 못 찾습니다** | 틀리면 바로 보입니다 |
| 내가 뭘 시켰는지 헷갈립니다 | 내가 뭘 정했는지 압니다 |
| 토큰이 훨씬 많이 듭니다 | 결과적으로 훨씬 적게 씁니다 |

조금 답답하실 수 있어요. 그래도 하나씩 하는 게 결국 제일 빠릅니다.

> 6주 뒤에 남는 건 사이트만이 아니라 **이 습관**입니다.

## 오늘 하는 것 4단계

### 1단계 · 작업 공간 만들기 (30분)

**1회차에 만든 폴더는 버리고, 오늘 제대로 된 자리를 만듭니다.**

폴더가 어디 생겼는지 못 찾으셨죠? 폴더가 어디에 만들어질지 아무도 안 정해줘서 그렇습니다. 오늘 그 자리를 정합니다.

> **왼쪽 메뉴 → 준비 → 작업 공간 만들기** 를 열고 순서대로 따라 하세요.
> 1단계부터 8단계까지 있고, 다 하면 20분쯤 걸립니다.

**끝나면 이렇게 됩니다.**

```
VSCode 창 하나
  왼쪽    → 내 프로젝트 폴더 (아직 텅 비어 있음)
  오른쪽  → Claude 채팅창 (모델 Opus · 모드 Auto)
```

**오늘 새로 하는 것 3개**

| | 뭘 |
|---|---|
| **Claude Code 확장 설치** | 검은 터미널 대신 **채팅창**으로 씁니다 |
| **모델 = Opus** | 내 말의 의도를 제일 잘 알아듣습니다 |
| **모드 = Auto** | "허용할까요?" 를 매번 안 물어봅니다 |

**폴더가 비어 있는 게 정상입니다.** 오늘은 파일을 안 만들어요.

### 2단계 · 참조 사이트 뜯어보기 (25분)

1. 참조하고 싶은 사이트를 브라우저에 엽니다
2. 화면을 스크린샷으로 저장합니다
3. Claude Code에 스크린샷을 주고 대화를 시작합니다

**프롬프트 — 대괄호 안만 내 것으로 바꾸세요**

```
나는 [               ] 사이트를 만들고 싶어.
쓰는 사람은 [               ].

첨부한 스크린샷은 참고하고 싶은 실제 사이트야.
이걸 참고해서, 내 사이트에 필요한 페이지 목록을 뽑아줘.
각 페이지에 뭐가 들어가는지도 같이 적어줘.

아직 코드는 만들지 마. 목록만.
```

**빈칸에 뭘 넣나요?**

| 빈칸 | 뭘 적나 | 이렇게 |
|---|---|---|
| 첫 번째 | **뭘 모아두는 사이트인지** | 내가 다녀온 카페를 기록하는 |
| 두 번째 | **누가, 왜 쓰는지** | 나 혼자, 다시 갈 곳을 고르려고 |

**다 채운 예시 3개** — 내 아이디어와 비슷한 걸 골라 흉내 내세요.

```
나는 [내가 다녀온 카페를 기록하는] 사이트를 만들고 싶어.
쓰는 사람은 [나 혼자, 다음에 다시 갈 곳을 고르려고].
```

```
나는 [내가 만든 작업물을 모아 보여주는] 사이트를 만들고 싶어.
쓰는 사람은 [나를 처음 보는 사람, 내가 뭘 하는 사람인지 알려고].
```

```
나는 [우리 동네 산책 코스를 소개하는] 사이트를 만들고 싶어.
쓰는 사람은 [광명에 사는 사람, 주말에 갈 곳을 찾으려고].
```

:::note[아이디어가 아직 흐릿해도 괜찮습니다]
"뭘 만들지 잘 모르겠어요"도 그대로 말하면 됩니다.

```
아직 뭘 만들지 확실하지 않아.
[산책], [기록], [사진] 이런 것에 관심이 있는데,
1인 사이트로 만들 만한 걸 3개만 제안해줘. 각각 한 줄 설명도 같이.
```

셋 중에 마음이 가는 걸 고르고 위 프롬프트로 넘어가세요.
:::

### 3단계 · AI와 대화하며 좁히기 (20분)

AI가 목록을 뽑아주면, 그대로 받지 마세요. **너무 많을 겁니다.**

**한 번에 하나씩.** 아래를 순서대로, 답을 읽고 다음으로 넘어가세요.

**① 줄이기**
```
6주 안에 혼자 만들 거야.
지금 목록에서 꼭 필요한 것만 남기고 줄여줘.
페이지는 3개 이하로.
```

**② 하나씩 파고들기** — 페이지 이름만 바꿔서 반복
```
[               ] 페이지에 뭐가 들어가야 하는지 더 구체적으로 알려줘.
```

**③ 왜 그런지 물어보기**
```
방금 [               ] 를 넣자고 했는데, 왜 필요한지 한 줄로 알려줘.
```

**④ 빼보기**
```
[               ] 를 빼면 뭐가 아쉬워져?
```

이렇게 20분 넘게 대화해보세요. **오늘은 AI와 오래 이야기하는 것 자체가 목적입니다.**

### 4단계 · 옆 사람에게 설명하기 (20분)

가장 중요한 시간입니다.

2인 1조로 앉아서, 자기 페이지 목록을 **말로 설명합니다.**

> "제 사이트는 홈이랑 상세, 두 페이지예요. 홈에는 카드가 쭉 있고..."

듣는 사람은 **자기 언어로 되물어보세요.**
> "이 페이지가 이런 뜻이에요?"
> "여기 이거 왜 넣었어요?"

**여기서 뭔가 일어납니다.** 설명하다가 자기 입으로 "어? 이 페이지 왜 넣었지?" 하게 돼요.
그 순간이 오늘의 핵심입니다.

```
- 나는 코딩을 모른다. 코드를 직접 쓰지 않는다.

## 작업 규칙
- 한국어로 답한다.
- 설명은 짧게. 세 줄을 넘기지 않는다.
- 파일을 고치기 전에, 무엇을 왜 바꿀지 한 줄로 먼저 말한다.
- 한 번에 파일 하나씩만 고친다.
- 한 번에 하나씩만 한다. 여러 개를 시키면 하나만 하고 나머지는 되물어라.

- 내가 요청하지 않은 파일은 건드리지 않는다.

## 하지 말 것
- `.env` 파일의 내용을 화면에 출력하지 않는다.
- API 키를 코드 안에 직접 적지 않는다. 반드시 `.env` 를 쓴다.
- 내가 이해하지 못할 것 같은 복잡한 구조를 만들지 않는다.

```
