## 오늘 미리 알아두면 좋은 것

**여기까지 오신 것만으로 충분해요.** 4회차가 제일 손이 많이 가는 회차였거든요.

오늘은 두 가지를 해요.
1. **남은 것 같이 이어가기** — 어디까지 오셨든 괜찮아요
2. **내 사이트에 옷 입히기** — 색, 글씨, 여백을 내가 원하는 느낌으로

**오늘의 알맹이는 두 번째예요.** 지금까지는 "되게" 만들었다면, 오늘은 "내 것처럼" 보이게 만듭니다.

그리고 **내일이 배포예요.**

**6일 동안 거의 못 만지셨어도 정말 괜찮아요.** 오늘 앞부분이 그걸 위해 있는 시간이거든요.

## 오늘 새로 준비하는 것 · Vercel 계정

**오늘은 가입까지만 해요.** 배포는 내일이거든요.

vercel.com → **GitHub 계정으로 로그인** (3초)

:::note[꼭 GitHub 계정으로 가입해주세요]
GitHub로 가입하면 내일 저장소 연결이 자동으로 돼요. 이메일로 가입하면 내일 한 단계가 더 늘어요.
:::

## GitHub는 이미 쓰고 계십니다

3회차와 4회차에 한 번씩 올려보셨죠. 오늘도 마지막에 한 번 더 올릴 거예요.

**왜 계속 올리나요**
내일 Vercel이 **GitHub에서 코드를 가져가서** 배포하거든요. 여기 코드가 없으면 가져갈 게 없어요.

**용어 세 개만 다시**

| 말 | 뜻 |
|---|---|
| **저장소 (repo)** | 프로젝트 하나가 통째로 들어가는 폴더 |
| **커밋 (commit)** | "여기까지 작업한 걸 저장" |
| **푸시 (push)** | 내 노트북에 저장한 걸 GitHub로 올리기 |

	<p class="doc-link-label">오늘 "빌드" 라는 말도 나옵니다</p>
	<p class="doc-link-to">왼쪽 메뉴 → 준비 → 개발 용어 6개</p>
	<p class="doc-link-desc">빌드·배포·린트가 각각 뭔지, 되돌리기 어려운 일 앞에서 AI를 멈춰 세우는 프롬프트까지 정리해뒀어요.</p>

:::caution[아직 안 올리셨어도 괜찮아요]
오늘 여기서 같이 하면 돼요. 이것부터 시켜보시면 됩니다.

```
이 프로젝트를 GitHub에 올려줘.
저장소 이름은 [my-site] 로, 비공개로 만들어줘.
.env 파일은 올라가지 않게 확인해줘.
```

`.env` 에는 Supabase 열쇠가 들어 있어서 **절대 올라가면 안 됩니다.** 프롬프트에 이미 넣어뒀어요.
:::

## 오늘 하는 것 4단계

### 1단계 · 지난 시간 이어서 하기 (25분)

**이 시간은 원래 이러라고 있는 거예요.** 4회차에서 다 못 끝내는 게 정상이거든요.

지금 어디쯤 계신지만 알려주시면 거기서부터 같이 봐드릴게요.

- 폼까지 만드셨으면 → 테이블 만드는 것부터
- 테이블까지 만드셨으면 → 연결하는 것부터
- 연결이 잘 안 되고 있으면 → 그 부분을 같이

**뭘 못 했는지 말하기 어려우시면 그냥 손만 들어주셔도 돼요.** 화면 보고 제가 찾을게요.

:::tip[저장이 안 되던 분은 이것부터 해보세요]
지난 시간 이후로 Supabase 쪽 규칙이 바뀐 게 하나 있어요. **자물쇠(RLS)를 풀어도 한 줄이 더 필요합니다.**

```
Supabase 테이블에 저장이 안 돼. RLS는 이미 열어놨어.
테이블 이름은 [reviews] 야.

anon 롤에 GRANT 를 주는 SQL을 뽑아줘.
SQL Editor에 붙여넣을 한 덩어리로.
```

**여기서 풀리는 경우가 꽤 있어요.** 안 풀려도 괜찮습니다. 그때 같이 봐드릴게요.
:::

1단계가 이미 끝나신 분은 **3단계 디자인부터 먼저 시작**하셔도 좋아요.

---

### 2단계 · 지금 상태 점검 (10분)

여섯 개를 하나씩 같이 볼게요.

- [ ] **기능 하나는 실제로 동작한다**
- [ ] **화면에 이미지가 하나 이상 있다**
- [ ] **브라우저 탭에 사이트 이름이 뜬다**
- [ ] **텍스트에 오타가 없다**
- [ ] **색과 글씨가 최소한 통일돼 있다**
- [ ] **휴대폰 화면에서도 안 깨진다**

> **6개를 다 못 하셔도 됩니다.** 4개 이상이면 내일 배포할 수 있어요.

:::tip[폰 화면은 이렇게 보시면 돼요]
폰에 `localhost:3000` 을 치면 안 열려요. **그 주소는 내 노트북 안에서만** 통하거든요.

**방법 1 · 브라우저 창을 좁게 줄이기 (확실한 방법)**

1. 창이 화면에 꽉 차 있으면 먼저 **창 크기를 줄여주세요.** 오른쪽 위 닫기(X) 바로 왼쪽 버튼이에요
2. 브라우저 창의 오른쪽 끝을 잡고 **왼쪽으로 쭉** 끌어보세요
3. 창이 폰만큼 좁아졌을 때 화면이 어떻게 되는지 봐주세요

**방법 2 · 진짜 폰으로 보기 (되면 좋고요)**

서버를 켤 때 뜬 `Network:` 줄의 주소(`http://192.168...` 같은 것)를 폰 브라우저에 치면, **같은 와이파이**에서는 열려요. 잘 안 되면 그냥 방법 1로 하셔도 충분합니다.

글씨가 겹치거나, 카드가 삐져나오거나, 옆으로 스크롤이 생기면 그게 "깨진" 거예요. 보이는 그대로 말하시면 돼요.

```
브라우저 창을 좁게 줄이면 [카드가 옆으로 삐져나와].
폰처럼 좁은 화면에서도 안 깨지게 고쳐줘.
```
:::

```
브라우저 탭에 뜨는 이름을 [내 카페 기록] 으로 바꿔줘.
```

### 3단계 · 내 사이트에 옷 입히기 (40분)

**오늘의 알맹이예요.** 지금까지는 "되게" 만들었고, 이제 "보기 좋게" 만들어요.

여기서 제일 흔한 실수가 있어요.

```
예쁘게 해줘
```

이렇게 시키면 **매번 다른 게 나와요.** 어제는 파란색, 오늘은 보라색. AI에게 기준이 없어서 그래요.

그래서 오늘은 순서대로 가볼게요. **① 느낌 정하기 → ② 기준 가져오기 → ③ 한 페이지씩 입히기.**

---

#### ① 내 사이트 느낌 정하기 (10분)

**"어떤 느낌으로 하고 싶으세요?" 라고 물으면 대부분 막막해하세요.** 당연해요. 저도 그렇거든요.

그래서 **고르기만 하면 되게** 만들어봤어요. 세 줄만 정하시면 됩니다.

| 고르는 것 | 왼쪽 ↔ 오른쪽 |
|---|---|
| **분위기** | 차분한 ↔ 활기찬 |
| **여백** | 널찍한 ↔ 촘촘한 |
| **모서리** | 둥근 ↔ 각진 |

예를 들면 이런 식이에요.

- 카페 기록 사이트 → **차분한 · 널찍한 · 둥근**
- 운동 기록 사이트 → **활기찬 · 촘촘한 · 각진**

**아직도 모르겠으면 이 방법이 확실해요.**

폰을 꺼내서 **평소 자주 들어가는 사이트나 앱 두세 개**를 열어보세요.
쇼핑몰이든 배달앱이든 상관없어요. 그중 보기 편했던 걸 하나 고르시면 됩니다.

그리고 그 이름을 그대로 말하시면 돼요.

```
[토스] 앱처럼 차분하고 여백이 넉넉한 느낌으로 가고 싶어.
지금 내 홈 화면을 그 느낌에 가깝게 바꾸려면
뭘 고쳐야 하는지 3개만 알려줘. 아직 고치지는 말고.
```

**"아직 고치지는 말고"** 가 중요해요. 뭘 바꿀지 먼저 보고 정하시는 거예요.

---

#### ② 기준을 파일로 만들어두기 (10분)

느낌을 정했으면, 그걸 **파일 한 장에 적어둡니다.** 그 파일이 `DESIGN.md` 예요.

**왜 파일로 만드나요**
말로 할 때마다 조금씩 달라지거든요. 파일에 적어두면 **AI가 매번 같은 기준을 봐요.**

두 가지 방법이 있어요.

<mark>오늘 처음이시면 A로 하세요.</mark> 10분 안에 끝나고, 결과도 충분히 괜찮습니다.
B는 20분쯤 걸려요. 시간이 남거나 집에서 더 해보고 싶으실 때 하시면 됩니다.

**A · 내가 정한 걸로 만들기 (오늘은 이걸로)**

```
DESIGN.md 라는 파일을 프로젝트 맨 위에 만들어줘.

내 사이트는 [차분한 · 널찍한 · 둥근] 느낌으로 가고 싶어.
[토스] 앱 같은 분위기야.

여기에 맞는 색 3~4개, 글씨 크기 단계, 간격 규칙을 정해서
그 파일에 정리해줘. 코드는 아직 고치지 마.
```

**B · 유명한 곳의 규칙을 가져오기 (시간 남으면)**

애플, 스포티파이, 토스 같은 곳의 디자인 규칙을 그대로 받아오는 방법이에요. 74곳이 정리돼 있습니다.

손이 조금 더 가는데, 확실히 그럴듯해져요.

#### ③ 한 페이지씩 입히기 (20분)

파일을 만들었다고 AI가 알아서 보지는 않아요. **읽으라고 한 번 말해줘야 해요.**

```
DESIGN.md 를 읽고, 그 기준대로 홈 화면의
색과 간격, 글씨 크기를 다시 잡아줘.

화면 구조와 기능은 건드리지 마.
```

:::caution[꼭 한 페이지씩 해주세요]
"전부 다 바꿔줘" 라고 하면 **파일을 열 개씩 고칩니다.** 4회차에 어렵게 붙인 기능이 같이 깨질 수 있어요.

홈이 마음에 들면 그때 다음 페이지로 가시면 됩니다.

```
좋아. 이제 [상세] 페이지도 같은 기준으로 해줘.
```
:::

**바뀐 게 마음에 안 드시면** 이 한 줄이면 돌아와요.

```
방금 바꾼 걸 되돌려줘. 그 전 상태로.
```

#### 조금씩 손보는 말들

한 번에 완성되지 않아요. **보고 → 한 군데 고치고 → 다시 보고.** 이걸 반복하시면 됩니다.

| 이렇게 느껴지면 | 이렇게 말하세요 |
|---|---|
| 답답하다 | "전체적으로 여백을 조금 더 넓혀줘" |
| 밋밋하다 | "버튼이랑 제목에만 포인트 색을 써줘" |
| 촌스럽다 | "색을 하나로 줄이고 나머지는 회색 계열로 가줘" |
| 글씨가 안 읽힌다 | "본문 글씨를 조금 키우고 줄 간격을 넓혀줘" |
| 다 비슷해 보인다 | "제목과 본문 크기 차이를 더 크게 벌려줘" |

**한 번에 하나씩만 말해주세요.** 세 개를 한꺼번에 시키면 어느 게 좋아진 건지 알 수가 없어요.

:::note[오늘 예쁘게 안 나와도 정말 괜찮아요]
디자인은 원래 한 번에 안 나와요. **디자이너들도 몇 번씩 고칩니다.**

색을 세 번 바꿔보고 처음 걸로 돌아가셔도 됩니다. 그게 이상한 게 아니라 원래 그런 일이에요.

오늘 목표는 "완벽한 디자인" 이 아니라 **"내가 골라봤다"** 예요. 그거면 충분합니다.
:::

:::tip[AI 티가 난다는 건 보통 이런 거예요]
색이 너무 많거나, 그림자가 진하거나, 보라색 그라데이션이 들어가 있으면 그렇게 느껴져요.

```
색을 줄이고 그림자를 옅게 해줘.
그라데이션은 빼고 단색으로 가줘.
```

이 한 줄이 생각보다 많이 바꿔줍니다.
:::

### 4단계 · 옆 사람에게 노트북 넘기기 (15분)

**오늘 제일 재미있는 시간이에요.**

2인 1조로 앉아서, **자기 노트북을 옆 사람에게 넘겨보세요.**

- **만지는 분:** 처음 온 사용자처럼 편하게 눌러보시면 돼요
- **만든 분:** 아무 말 안 하고 보기만 해주세요

3분씩 하고 짝을 바꿔요.

여기서 이런 말이 나와요.
> "여기가 뭐예요?"
> "이거 눌렀는데 왜 안 되죠?"

그게 오늘 제일 값진 발견이에요.

내 눈엔 당연했던 게 처음 오는 사람 눈엔 안 보이거든요. 배포하기 전에 알게 돼서 다행인 거예요.

> 너무 마음에 담아두지 않으셔도 됩니다. 옆 사람이 못 알아본 건 여러분이 잘못한 게 아니에요.
> 처음 오는 사용자 눈으로 보면 다들 그렇게 보입니다.

### 마지막 · 한 번 점검하고 GitHub에 올리기

옆 사람에게 들은 걸 먼저 고치고, 그다음 **점검과 저장을 한 번에** 시켜볼게요.

```
npm run build 를 실행해서 에러가 없는지 확인해줘.
에러가 있으면 뭐가 문제인지 알려주고 하나씩 고쳐줘.

에러가 없으면 그대로 GitHub에 올려줘.
커밋 메시지는 "5회차 완성" 으로 하고, .env 는 올라가지 않게 확인해줘.
```

:::note[이 점검을 오늘 해두면 내일이 편해요]
내일 Vercel에 올릴 때도 **똑같은 점검**을 하거든요. 오늘 걸러두면 내일 그만큼 수월해져요.

내 노트북에서 잘 돌아가도 이 점검에서는 걸릴 수 있어요. 그래서 미리 한 번 돌려보는 거예요.

초록색으로 성공 메시지가 뜨고 GitHub에 올라갔다는 답이 오면 다 된 거예요.
:::
