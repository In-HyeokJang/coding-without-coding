## GitHub는 이미 쓰고 계십니다

3회차와 4회차에 한 번씩 올려보셨죠. 오늘도 마지막에 한 번 더 올립니다.

**왜 계속 올리나요**
내일 Vercel이 **GitHub에서 코드를 가져가서** 배포합니다. 여기 코드가 없으면 배포가 안 돼요.

**용어 세 개만 다시**

| 말 | 뜻 |
|---|---|
| **저장소 (repo)** | 프로젝트 하나가 통째로 들어가는 폴더 |
| **커밋 (commit)** | "여기까지 작업한 걸 저장" |
| **푸시 (push)** | 내 노트북에 저장한 걸 GitHub로 올리기 |

:::caution[3회차에 올린 적이 없으시면 오늘 꼭 하고 가세요]
내일 배포하려면 **GitHub에 내 코드가 올라가 있어야 합니다.** 아직이시면 이걸 먼저 해주세요.

```
이 프로젝트를 GitHub에 올려줘.
저장소 이름은 [my-site] 로, 비공개로 만들어줘.
.env 파일은 올라가지 않게 확인해줘.
```

`.env` 에는 Supabase 열쇠가 들어 있어서 **절대 올라가면 안 됩니다.** 프롬프트에 이미 넣어뒀어요.
:::

## 오늘 하는 것 3단계

### 1단계 · 격차 좁히기 (30분)

**4회차에서 못 끝내신 분 먼저입니다.**

- Supabase 연결이 안 된 분 → 오늘 같이 뚫습니다
- 폼까지만 있던 분 → 로컬 상태부터 마무리

이미 다 되신 분은 이 시간에 다듬기를 먼저 시작하시면 좋아요. 그리고 옆 사람도 한 번 봐주세요.

오늘 안에 6명 다 "동작하는 사이트"까지 갑니다.

---

### 2단계 · 완성 체크리스트 (30분)

여섯 개를 하나씩 확인합니다.

- [ ] **기능 하나는 실제로 동작한다**
- [ ] **화면에 이미지가 하나 이상 있다**
- [ ] **브라우저 탭에 사이트 이름이 뜬다**
- [ ] **텍스트에 오타가 없다**
- [ ] **색과 글씨가 최소한 통일돼 있다**
- [ ] **휴대폰 화면에서도 안 깨진다**

> **6개를 다 못 하셔도 됩니다.** 4개 이상이면 내일 배포할 수 있어요.

> 💡 **AI 티 나는 디자인이 걱정된다면?**  
> AI에게 "AI 팀 프롬프트"나 디자인 스킬을 활용해 다듬어 달라고 시켜보세요.  
> `"UI/UX 디자이너 AI 관점에서 이 페이지의 색감과 간격을 세련되고 고급스럽게 다시 잡아줘."`

### 3단계 · 옆 사람에게 노트북 넘기기 (20분)

**오늘의 진짜 순서입니다.**

2인 1조로 앉아서, **자기 노트북을 옆 사람에게 넘겨보세요.**

- **만지는 분:** 처음 온 사용자처럼 자연스럽게 눌러보세요
- **만든 분:** 개입하지 마시고 보기만 해주세요

3분씩 하고 짝을 바꿉니다.

여기서 이런 말이 나옵니다.
> "여기가 뭐예요?"
> "이거 눌렀는데 왜 안 되죠?"

그게 오늘 제일 중요한 발견이에요.

내 눈엔 당연했던 게 처음 오는 사람 눈엔 안 보입니다. 배포 전에 발견해서 다행인 거예요.

> 너무 마음에 담아두지 않으셔도 됩니다. 옆 사람이 못 알아본 건 여러분이 잘못한 게 아니에요.
> 처음 오는 사용자 눈으로 보면 다들 그렇게 보입니다.

### 마지막 · 배포 예행연습 + GitHub 푸시

옆 사람에게 들은 걸 먼저 고치고, 그다음 **검사와 저장을 한 번에** 시킵니다.

```
npm run build 를 실행해서 에러가 없는지 확인해줘.
에러가 있으면 뭐가 문제인지 알려주고 하나씩 고쳐줘.

에러가 없으면 그대로 GitHub에 올려줘.
커밋 메시지는 "5회차 완성" 으로 하고, .env 는 올라가지 않게 확인해줘.
```

:::caution[`npm run build` 가 내일 사고를 막아줍니다]
내일 Vercel에 올릴 때도 **똑같은 검사**를 합니다. 여기서 걸리는 게 있으면 배포가 통째로 멈춰요.

내 노트북에서 잘 돌아가도 이 검사에서는 막힐 수 있습니다. 오늘 미리 걸러두는 게 훨씬 마음 편해요.

초록색으로 성공 메시지가 뜨고 GitHub에 올라갔다는 답이 오면 통과입니다.
:::

**완벽하지 않아도 괜찮습니다.** 여기서 확정하고 넘어가요. 내일이 배포니까요.
