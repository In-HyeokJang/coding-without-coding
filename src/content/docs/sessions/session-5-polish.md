## 오늘 미리 알아두면 좋은 것

**여기까지 오신 것만으로 충분해요.** 4회차가 제일 손이 많이 가는 회차였거든요.

오늘은 두 가지를 해요.
1. **남은 것 같이 이어가기** — 어디까지 오셨든 괜찮아요
2. **보기 좋게 다듬기** — 색, 글씨, 이미지, 오타

그리고 **내일이 배포예요.**

**6일 동안 거의 못 만지셨어도 정말 괜찮아요.** 오늘 앞 30분이 그걸 위해 있는 시간이거든요.

---

## 오늘 새로 준비하는 것 · Vercel 계정

**오늘은 가입까지만 해요.** 배포는 내일이거든요.

vercel.com → **GitHub 계정으로 로그인** (3초)

:::note[꼭 GitHub 계정으로 가입해주세요]
GitHub로 가입하면 내일 저장소 연결이 자동으로 돼요. 이메일로 가입하면 내일 한 단계가 더 늘어요.
:::

## GitHub는 이미 쓰고 계십니다

3회차와 4회차에 한 번씩 올려보셨죠. 오늘도 마지막에 한 번 더 올릴 거예요.

**왜 계속 올리나요**
내일 Vercel이 **GitHub에서 코드를 가져가서** 배포하거든요. 여기 코드가 없으면 가져갈 게 없어요.

**용어 세 개만 다시**

| 말 | 뜻 |
|---|---|
| **저장소 (repo)** | 프로젝트 하나가 통째로 들어가는 폴더 |
| **커밋 (commit)** | "여기까지 작업한 걸 저장" |
| **푸시 (push)** | 내 노트북에 저장한 걸 GitHub로 올리기 |

:::caution[아직 안 올리셨어도 괜찮아요]
오늘 여기서 같이 하면 돼요. 이것부터 시켜보시면 됩니다.

```
이 프로젝트를 GitHub에 올려줘.
저장소 이름은 [my-site] 로, 비공개로 만들어줘.
.env 파일은 올라가지 않게 확인해줘.
```

`.env` 에는 Supabase 열쇠가 들어 있어서 **절대 올라가면 안 됩니다.** 프롬프트에 이미 넣어뒀어요.
:::

## 오늘 하는 것 3단계

### 1단계 · 지난 시간 이어서 하기 (30분)

**이 30분은 원래 이러라고 있는 시간이에요.** 4회차에서 다 못 끝내는 게 정상이거든요.

지금 어디쯤 계신지만 알려주시면 거기서부터 같이 봐드릴게요.

- 폼까지 만드셨으면 → 테이블 만드는 것부터
- 테이블까지 만드셨으면 → 연결하는 것부터
- 연결이 잘 안 되고 있으면 → 그 부분을 같이

**뭘 못 했는지 말하기 어려우시면 그냥 손만 들어주셔도 돼요.** 화면 보고 제가 찾을게요.

이미 다 되신 분은 이 시간에 다듬기를 먼저 시작하셔도 좋아요.

---

### 2단계 · 완성 체크리스트 (30분)

여섯 개를 하나씩 같이 볼게요.

- [ ] **기능 하나는 실제로 동작한다**
- [ ] **화면에 이미지가 하나 이상 있다**
- [ ] **브라우저 탭에 사이트 이름이 뜬다**
- [ ] **텍스트에 오타가 없다**
- [ ] **색과 글씨가 최소한 통일돼 있다**
- [ ] **휴대폰 화면에서도 안 깨진다**

> **6개를 다 못 하셔도 됩니다.** 4개 이상이면 내일 배포할 수 있어요.

:::tip[폰 화면은 이렇게 보시면 돼요]
폰에 `localhost:3000` 을 치면 안 열려요. **그 주소는 내 노트북 안에서만** 통하거든요.

**방법 1 · 브라우저 창을 좁게 줄이기 (확실한 방법)**

1. 창이 화면에 꽉 차 있으면 먼저 **창 크기를 줄여주세요.** 오른쪽 위 닫기(X) 바로 왼쪽 버튼이에요
2. 브라우저 창의 오른쪽 끝을 잡고 **왼쪽으로 쭉** 끌어보세요
3. 창이 폰만큼 좁아졌을 때 화면이 어떻게 되는지 봐주세요

**방법 2 · 진짜 폰으로 보기 (되면 좋고요)**

서버를 켤 때 뜬 `Network:` 줄의 주소(`http://192.168...` 같은 것)를 폰 브라우저에 치면, **같은 와이파이**에서는 열려요. 잘 안 되면 그냥 방법 1로 하셔도 충분합니다.

글씨가 겹치거나, 카드가 삐져나오거나, 옆으로 스크롤이 생기면 그게 "깨진" 거예요. 보이는 그대로 말하시면 돼요.

```
브라우저 창을 좁게 줄이면 [카드가 옆으로 삐져나와].
폰처럼 좁은 화면에서도 안 깨지게 고쳐줘.
```
:::

**AI 티 나는 디자인이 걱정되시면** 이렇게 한 번 시켜보세요.

```
UI/UX 디자이너 관점에서 이 페이지의
색감과 간격을 세련되게 다시 잡아줘.
기능은 건드리지 마.
```

	<p class="doc-link-label">색과 간격에 기준을 두고 싶다면</p>
	<p class="doc-link-to">왼쪽 메뉴 → 준비 → 디자인 가져다 쓰기</p>
	<p class="doc-link-desc">유명 브랜드의 디자인 규칙을 DESIGN.md 로 가져와서 그 기준대로 만들게 하는 방법이에요. 디자인을 대신 다듬어주는 도구(frontend-design)는 왼쪽 메뉴 → 준비 → 더 써보고 싶다면 에 있어요.</p>
</div>

**프롬프트 모음**

```
지금 화면에서 이 부분을 고치고 싶어:
- 제목 글씨가 너무 작아. 두 배 정도 크게
- 카드 사이 간격이 좁아. 조금 띄워줘
- 배경이 흰색인데 아주 옅은 회색으로

한 번에 하나씩 하고, 하고 나면 알려줘.
```

```
브라우저 탭에 뜨는 이름을 [내 카페 기록] 으로 바꿔줘.
```

```
휴대폰 화면에서 봤을 때도 안 깨지게 해줘.
```

### 3단계 · 옆 사람에게 노트북 넘기기 (20분)

**오늘 제일 재미있는 시간이에요.**

2인 1조로 앉아서, **자기 노트북을 옆 사람에게 넘겨보세요.**

- **만지는 분:** 처음 온 사용자처럼 편하게 눌러보시면 돼요
- **만든 분:** 아무 말 안 하고 보기만 해주세요

3분씩 하고 짝을 바꿔요.

여기서 이런 말이 나와요.
> "여기가 뭐예요?"
> "이거 눌렀는데 왜 안 되죠?"

그게 오늘 제일 값진 발견이에요.

내 눈엔 당연했던 게 처음 오는 사람 눈엔 안 보이거든요. 배포하기 전에 알게 돼서 다행인 거예요.

> 너무 마음에 담아두지 않으셔도 됩니다. 옆 사람이 못 알아본 건 여러분이 잘못한 게 아니에요.
> 처음 오는 사용자 눈으로 보면 다들 그렇게 보입니다.

### 마지막 · 한 번 점검하고 GitHub에 올리기

옆 사람에게 들은 걸 먼저 고치고, 그다음 **점검과 저장을 한 번에** 시켜볼게요.

```
npm run build 를 실행해서 에러가 없는지 확인해줘.
에러가 있으면 뭐가 문제인지 알려주고 하나씩 고쳐줘.

에러가 없으면 그대로 GitHub에 올려줘.
커밋 메시지는 "5회차 완성" 으로 하고, .env 는 올라가지 않게 확인해줘.
```

:::note[이 점검을 오늘 해두면 내일이 편해요]
내일 Vercel에 올릴 때도 **똑같은 점검**을 하거든요. 오늘 걸러두면 내일 그만큼 수월해져요.

내 노트북에서 잘 돌아가도 이 점검에서는 걸릴 수 있어요. 그래서 미리 한 번 돌려보는 거예요.

초록색으로 성공 메시지가 뜨고 GitHub에 올라갔다는 답이 오면 다 된 거예요.
:::

**완벽하지 않아도 정말 괜찮아요.** 오늘은 여기까지만 하고 넘어가도 충분합니다.
