## [1.2] · 2026-07-29

### 더한 것

- **준비 → 작업 공간 만들기** 문서 새로 추가
  1회차에 프로젝트 폴더는 만들었는데 **그게 어디 있는지 못 찾는 문제**가 실제로 생겼습니다.
  폴더가 어디 만들어질지 아무도 안 정해준 탓이라, **1회차 폴더는 버리고 새 자리에서 다시 시작**하기로 했습니다.
  드라이브 확인 → `workspace` 만들기 → 1회차 폴더 지우기 → 프로젝트 폴더 새로 만들기 →
  VSCode로 열기 → VSCode 안에서 Claude Code 켜기 → 모델 설정까지, 클릭 하나하나를 다 적었습니다.
  2회차에는 폴더가 비어 있는 게 정상이라는 것도 명시했습니다(실제 사이트 파일은 3회차에 생깁니다).
- 모델은 **`default`** 를 쓰도록 안내했습니다. `opus`로 바꿨다가 회차 중간에 사용량 한도가
  차면 남은 시간을 통째로 못 쓰기 때문입니다.

### 고친 것

- **문서 안의 안내를 전부 한글 메뉴 이름으로 통일**
  `core/03-token-setup.md` 처럼 파일 이름으로 안내하던 곳을 **준비 → 토큰 절약 설정** 처럼
  왼쪽 메뉴에 실제로 보이는 이름으로 바꿨습니다. 참가자가 찾아갈 수 없는 표기였습니다.
- 각 문서 맨 아래 서명도 `core/01` → `도구 6종` 처럼 메뉴 이름으로 변경

> 참가자가 직접 만드는 파일(`CLAUDE.md`, `AGENTS.md`, `.env`)은 실제 파일 이름이므로 그대로 뒀습니다.

### 2회차 · 프롬프트 가이드 · 토큰 절약 설정 손봄

- **2회차** — `오늘의 규칙`을 오프닝으로 올리고 **"한 번에 하나만 물어보기"** 를 1번 규칙으로 신설.
  1단계에 작업 공간 만들기를 넣고, 프롬프트를 **빈칸 채우기식 + 예시 3개**로 교체.
  마무리에 **내 CLAUDE.md 만들기** 단계 추가(템플릿을 주고 AI가 내 아이디어에 맞게 고쳐 만들게 함).
- **토큰 절약 설정** — 빈 폴더에서 `/init` 을 쓰지 말라고 명시.
  `/init` 은 폴더 안 파일을 훑는 명령어라 2회차(빈 폴더)에는 빈 껍데기만 나옵니다.
  회차 번호를 실제 진행에 맞게 정정(1회차 → 2회차), 모델 설정 항목 연결.
- **프롬프트 가이드** — 프로젝트 생성 템플릿을 1회차에서 **3회차로 이동**.
  1회차에 만든 폴더를 버리기로 해서, 프로젝트는 3회차에 새로 만듭니다.

### 고침 · 없어진 명령어

- **`/stats` → `/usage`**
  1.0에 적어둔 `/stats` 는 지금 Claude Code에 **없는 명령어**입니다. 사용량 확인은 `/usage`(또는 `/cost`)입니다.
- 모델 선택지에 **`Auto` 라는 이름의 옵션은 없습니다.** 그 역할을 하는 건 **`default`** 입니다.

## [1.1] · 2026-07-28

### 고친 것

- **타임캡슐 · 저장 실패인데 "봉인 성공"으로 보이던 문제 수정**
  Supabase 저장에 실패해도 화면에는 성공이 떴습니다. 그러면 6회차에 열 게 아무것도 없습니다.
  이제 **진짜 저장된 경우에만** 성공 화면이 뜨고, 실패하면 이유와 함께 빨간 안내가 나오고 다시 시도할 수 있습니다.
- **타임캡슐 · 봉인 후 수정 불가 처리**
  같은 이름으로 이미 봉인된 캡슐이 있으면 새로 못 씁니다(덮어쓰기 방지).
  한 번 봉인한 브라우저에서는 폼 대신 "이미 봉인을 마쳤습니다" 화면이 뜹니다.
- **타임캡슐 · 암호 재사용 경고 추가**
  4자리 암호는 그대로 저장됩니다. 평소 쓰는 비밀번호를 넣지 말라는 경고를 폼과 **1회차 · 아이디어**에 넣었습니다.
- **1회차 · 아이디어** — 봉인 전 주의 안내(수정 불가 · 이름과 암호 메모) 추가
- **6회차 · 배포** — 개봉할 때 1회차의 이름·암호를 그대로 넣어야 한다는 안내 추가

### 확인한 것 (2026-07-28 기준)

- Claude Code `2.1.214` · 플러그인은 `/plugin`, 설정은 `~/.claude/settings.json`의 `enabledPlugins`
- Supabase `time_capsules` 테이블: 조회·저장·삭제 모두 정상 동작 확인
- 회차 자동 공개 시간을 **19:25 KST(모임 5분 전)** 로 변경

### 남은 숙제

- `time_capsules` 의 anon 권한이 너무 넓습니다. 지금은 **누구나 전체 조회·삭제가 가능**합니다.
  시즌 2 전에 RLS 정책을 조여야 합니다.
