## [2.2] · 2026-08-02

### 더한 것 · **개발 용어 6개** 문서

준비 메뉴에 새 문서를 추가했습니다. 도구 6종 바로 뒤에 있습니다.

우리 문서는 커밋·푸시·빌드·배포를 계속 쓰는데 **뜻 설명은 5회차 표에 세 줄뿐**이었습니다.
리팩터링과 린트는 아예 없었고요. AI가 "빌드가 실패했어요" 라고 하면 참가자가
어느 단계에서 막힌 건지 짐작할 방법이 없었습니다.

여섯 개를 일상 비유로 풀었습니다.

- **커밋** — 게임 세이브 (내 노트북에만)
- **푸시** — 창고로 갖다 두기 (인터넷으로)
- **빌드** — 레고 조립해보기
- **배포** — 세상에 내놓기
- **린트** — 코드 맞춤법 검사
- **리팩터링** — 겉은 그대로, 속만 정리

**이 문서의 핵심은 마지막 절입니다.** 여섯 프롬프트에 전부 같은 말을 넣었어요.

> 아직 하지 말고 먼저 보여줘. 내가 좋다고 하면 그때.

우리는 **Auto 모드**를 씁니다. 안 물어보고 진행하니 편한데, AI가 뭘 했는지 나중에 알게 돼요.
그래서 되돌리기 어려운 일(커밋·푸시·배포·리팩터링) 앞에서는 직접 멈춰 세우게 했습니다.

빌드 프롬프트에는 `문제를 숨기려고 설정을 마음대로 바꾸지는 마` 를 넣었습니다.
빌드 에러는 설정을 꺼버리면 통과되는데, 그러면 진짜 문제가 나중에 사이트에서 터집니다.

**연결** — 3회차 GitHub 저장 자리와 5회차 용어 표에 링크를 걸었습니다.

### 더한 것 · security-guidance 스킬

**더 써보고 싶다면** 목록에 Anthropic 공식 스킬을 하나 추가했습니다.
코드에 API 키가 그대로 남아 있으면 잡아줍니다.

우리는 4회차에 Supabase 열쇠를 다루면서 `.env` 를 쓰라고 계속 안내하는데,
**사람이 확인하는 것보다 도구가 확인하는 게 확실합니다.** 6개 중 제일 먼저 해봐도 좋다고 적었습니다.

### 더한 것 · MCP 2개, 그리고 안 넣은 이유

- **github** — 3회차부터 GitHub를 쓰는데 웹 화면 대신 대화로 처리하고 싶을 때
- **supabase** — 4회차에 테이블을 제대로 만들었는지 확인하고 싶을 때

인터넷에 도는 "MCP 24종" 목록(슬랙·리니어·피그마·도커·센트리 등)은 **대부분 넣지 않았습니다.**
회사에서 여럿이 일할 때 쓰는 것들이라, 혼자 페이지 3개짜리 사이트를 만드는 데는 쓸 일이 없어요.
없는 걸 붙이면 클로드가 굳이 일을 만들어냅니다. 그 이유도 문서에 적어뒀습니다.

## [2.1] · 2026-08-01

### 바꿈 · 3회차에서 왔다 갔다 하던 걸 한 번으로

같은 일을 하는 데 **다섯 번 왔다 갔다** 하고 있었습니다.

```
프로젝트 만들기 → 화면 켜기 → AI 팀 부르기 → CLAUDE.md 확인 → 페이지 만들기
```

AI는 시킬 때마다 **앞의 대화를 처음부터 다시 읽습니다.** 나눌수록 그만큼 사용량이 나가요.

**두 번으로 줄였습니다.**

```
① CLAUDE.md 확인 (30초)  →  ② 한 번에 시키기
```

②에 팀 소집·프로젝트 생성·페이지 전부·링크가 다 들어 있습니다.

- **프로젝트 생성을 따로 안 시킵니다.** 1회차에 이미 해본 것이라 또 할 필요가 없어요.
  `이 폴더에 Next.js 프로젝트가 아직 없으면 먼저 만들어줘` 한 줄로 프롬프트에 넣었습니다.
  (2회차에 1회차 폴더를 버려서 파일 자체는 없는 상태라, 아예 뺄 수는 없었습니다.)
- **"화면 먼저 켜기"를 뺐습니다.** 켜봤자 Next.js 로고 화면이라 참가자에게 의미가 없었어요.
  이제 켜면 **내 사이트가 바로** 뜹니다.
- **"한 번에 하나만" 원칙과 어긋나 보이는 것**에 대해 note를 달았습니다.
  이건 한 가지 일(내 사이트 뼈대 세우기)이라 한 덩어리가 맞습니다. 고치는 단계부터 하나씩 갑니다.

**바뀐 시간 배분** — 1단계 35분 / 2단계 25분 / 3단계 30분 / GitHub 10분 / 마무리 10분

**프롬프트 가이드**의 3회차 템플릿도 같은 모양으로 맞췄습니다.

### 고침 · 5회차에 푸시 프롬프트가 사라져 있었습니다

"GitHub, 드디어 씁니다" 절을 걷어내면서 **푸시 프롬프트까지 같이 날아갔습니다.**
"GitHub에 올립니다" 라고만 적혀 있고 어떻게 올리는지가 없었어요.

빌드 검사와 묶어서 **한 프롬프트**로 되살렸습니다. 검사 통과하면 그대로 올라갑니다.

### 고침 · 6회차에서 어제 것을 또 올리고 있었습니다

5회차 마지막에 이미 올렸는데 6회차 1단계가 무조건 다시 올리라고 했습니다.
바뀐 게 없으면 헛일이에요. **조건부로 바꾸고, 건너뛰어도 된다고 적었습니다.**

```
어제 이후로 바뀐 게 있으면 GitHub에 올려줘. 없으면 없다고만 알려줘.
```

> **4회차의 "폼 먼저 → 그다음 Supabase" 는 그대로 뒀습니다.** 이건 낭비가 아니라
> "여기까진 6명 다 성공합니다" 라는 의도된 중간 지점이라서요.

- **언제 쓰지 말아야 하는지**도 표로 넣었습니다. 3·4회차에는 쓰지 않습니다.
- **브랜드 이름과 로고는 쓰지 말라는 주의**를 넣었습니다. 규칙을 참고하는 것이지
  그 브랜드가 되는 게 아니니까요.

**연결**

- **더 써보고 싶다면** — DESIGN.md 절을 짧게 줄이고 새 문서로 넘기는 링크를 걸었습니다

### 고침 · 1~6회차를 순서대로 따라가며 발견한 것

전체를 처음부터 끝까지 읽으면서 앞뒤가 안 맞는 곳을 찾았습니다.

**GitHub 시점이 문서마다 달랐습니다.** 3회차에 첫 푸시를 하도록 바꿨는데, 다른 문서들은
여전히 "GitHub는 5회차부터" 라고 안내하고 있었습니다.

- **도구 6종** — 흐름도의 `코드를 올림 · 5회차` → `3회차부터`.
  GitHub 절의 회차 표를 1회차(계정) / 3회차(첫 푸시) / 4·5회차(추가)로 고치고, 왜 미리 올리는지 적었습니다.
- **1회차** — "실제로 쓰는 건 5회차예요" → **3회차**
- **5회차** — "GitHub, 드디어 씁니다" 절을 걷어냈습니다. 이미 두 번 올려본 뒤니까요.
  대신 "3회차에 안 올리셨으면 오늘 꼭" 안내를 caution으로 남겼습니다.
  이 자리는 **Vercel 계정 만들기**로 바꿨습니다.

**4회차 구조가 어긋나 있었습니다.**

- "오늘 하는 것 **2단계**" 인데 실제로는 3단계였습니다.
- **GitHub 절이 "에러가 났을 때" 섹션 안에 들어가 있었습니다.** 목차에서 에러 대응의
  하위 항목으로 보였어요. 밖으로 빼서 3단계로 세웠습니다.
- **"3단계"가 두 뜻으로 쓰이고 있었습니다.** 에러 대응 3단계 / 3단계 GitHub.
  앞쪽을 "에러가 나면 이 순서로" 로 바꿨습니다.

**4회차 프롬프트가 카페 리뷰 전용으로 굳어 있었습니다.**
`카페 이름, 별점, 한 줄 평` 과 `테이블 reviews` 가 대괄호 없이 박혀 있어서, 다른 아이디어인
참가자가 그대로 붙여넣으면 엉뚱한 게 만들어집니다. 대괄호로 바꾸고 다른 예시를 붙였습니다.

**1회차에 "이 폴더는 2회차에 다시 만든다" 는 안내가 없었습니다.**
2회차에 와서 갑자기 버리라고 하니 당황스러웠을 겁니다. 1회차 끝에 이유와 함께 적었습니다.

**4회차 · 3회차 연결이 어긋나 있었습니다.** "어제 만든 홈 화면" → 3회차가 바뀌었으니
"어제 만든 화면들 (클릭해서 돌아다녀지는 그 상태)" 로.

### 바꿈 · TypeScript 를 켜기로 했습니다

1.0부터 계속 `TypeScript 없이` 로 프로젝트를 만들게 하고 있었습니다. **판단이 틀렸습니다.**

- **껐던 이유가 약했습니다.** "규칙이 늘면 에러도 는다, 참가자는 코드를 못 고치니 에러가 적은 쪽이 낫다"
  였는데, 정작 우리가 3회차에 가르치는 게 **"에러 메시지를 그대로 붙여넣기"** 입니다. 앞뒤가 안 맞았어요.
- **타입은 참가자보다 AI를 돕습니다.** AI는 홈에서 `별점`, 상세에서 `평점` 이라고 부르는 실수를 자주 합니다.
  TypeScript면 그 자리에 바로 표시가 떠서 AI가 스스로 고칩니다. 없으면 아무 말 없이 넘어가고
  화면에 **빈칸**이 나옵니다. 빈칸이 제일 곤란해요. 에러 메시지가 없으니 AI에게 붙여넣을 게 없거든요.
- **커뮤니티가 끝난 뒤를 생각하면 더 그렇습니다.** `create-next-app` 의 기본값이 TypeScript이고,
  요즘 AI 코딩 도구는 전부 TypeScript로 코드를 뱉습니다. 여기서 익숙해져 두는 편이 이득입니다.

고친 곳은 네 군데입니다.

- **1회차 · 3회차 · 프롬프트 가이드** — `TypeScript 없이` → `TypeScript로`
- **2회차 · 토큰 절약 설정** — `CLAUDE.md` 템플릿 스택에 `+ TypeScript` 추가
- **3회차** — 설명 note를 다시 썼습니다. 리뷰 하나를 예로 들어
  (카페 이름 → 글자, 별점 → 숫자) 무슨 뜻인지 보이게 하고, 왜 AI를 돕는지 적었습니다.

### 더한 것 · 5회차 배포 예행연습

TypeScript를 켜면 **타입 에러 하나로 Vercel 배포가 통째로 멈출 수 있습니다.** 대비를 넣었습니다.

- **5회차 마지막 절 이름을 "배포 예행연습 + GitHub 푸시" 로 바꿨습니다.**
  GitHub에 올리기 전에 `npm run build` 로 한 번 걸러냅니다. 내일 Vercel이 하는 검사와 같은 검사예요.
- **프롬프트 가이드 5회차**에도 같은 프롬프트를 넣었습니다.

### 더한 것 · 중요한 안내에 색 넣기

- **문장 안 핵심 구절용 형광펜(`<mark>`)도 만들었습니다.** 글자 아래쪽만 코랄로 칠해집니다.
  한 화면에 하나 정도만 씁니다. 여러 개 쓰면 강조가 죽어서요.

- **딱딱한 말투를 부드럽게 풀었습니다.** "~합니다" 로 끊던 문장을 "~하시면 돼요",

앞으로도 같은 기준으로 쓰도록 프로젝트 규칙에 네 절을 넣었습니다.

- **강조** — 문서 안내는 코랄 박스, 핵심 구절은 `<mark>`
- **가독성** — 폰 기준. ASCII 그림 금지, 코드블록에 긴 문장 금지, 표는 2열 기본

### 바꿈 · 터미널 대신 VSCode 확장으로

- **검은 터미널에 `claude` 를 치는 방식을 걷어냈습니다.**
  대신 **Claude Code VSCode 확장**을 설치하고 **✱ 스파크 아이콘**으로 채팅창을 엽니다.
- **✱ 아이콘은 파일을 열어놨을 때만 편집기 오른쪽 위에 나타납니다.**
  2회차에는 폴더가 비어 있어 그 아이콘이 안 보입니다. 고장이 아니므로,
  **왼쪽 세로 막대**와 **오른쪽 아래 `✱ Claude Code`** 라는 대안을 함께 적었습니다.
- **모델은 `Opus`.** 코드를 직접 안 쓰는 우리에게는 **의도를 정확히 알아듣는 것**이 가장 중요합니다.
  가벼운 모델은 빠르지만 "내가 원한 게 이게 아닌데"가 잦아 되레 시간이 더 듭니다.
  사용량이 걱정될 때를 위해 `/usage` 확인과 Sonnet으로 내리는 방법도 함께 남겼습니다.
- **모드는 `Auto`.** Manual로 두면 10분에 스무 번씩 "허용할까요?"가 뜨는데,
  코드를 모르는 참가자는 **물어봐도 판단할 수 없어** 결국 "예"만 누르게 됩니다.
  Auto는 별도 분류 모델이 뒤에서 검사해 위험한 동작만 골라 막습니다.
  대신 1회차의 "`y` 누르기 전에 멈추기" 규칙을 **"끝나고 뭘 했는지 물어보기"** 로 대체했습니다.

### 고침 · 없어진 명령어

- **`/stats` → `/usage`**
  1.0에 적어둔 `/stats` 는 지금 Claude Code에 **없는 명령어**입니다. 사용량 확인은 `/usage`(또는 `/cost`)입니다.
- 모델 선택지에 **`Auto` 라는 이름의 옵션은 없습니다.** 그 역할을 하는 건 **`default`** 입니다.
